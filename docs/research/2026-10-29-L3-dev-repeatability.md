# L3: повторюваність двох помилок dev

Дата: 29.10.2026. Окремий діагностичний експеримент за прямою згодою власника після [початкового dev](2026-10-29-round-2-dev-results.md). **Не holdout, не заміна початкових результатів, не зміна промпту.**

## Умови

- L3: Gemma3-12B IT, власна Q4_K_M, SHA і recipe у [provenance](round2/weights-provenance.json).
- Чотири старі dev-приклади: `nude-clean`, `nude-issue`, `intimacy-clean`, `intimacy-issue`. На кожному — **3 нові генерації**, разом12. Старі checkpoint не використовувалися як нові відповіді; перевірено12 різних provider completion IDs.
- `model=l3`, context32768, batch512, Flash Attention/KV GPU, temp0,1, output4096, reasoning none, protocol3 `check/current_consistency`. Body кожного запиту структурно звірено з відповідним початковим dev-запитом; echo load config повністю збігся. Поточний парний UI38 / engine39 профіль не змінювали під час серії.
- Три блоки по чотири приклади; порядок перемішаний з seed20261029. Seed задає лише порядок, **не sampling моделі**. Для кожного прикладу prompt/schema/input однакові в усіх повторах. Ні schema, ні система оцінювання, ні корпус не налаштовувалися.
- Один HTTP-виклик на відповідь, без транспортних повторів, ремонту JSON або заміни `complete`. Усі результати збережено окремо в ignored `artifacts/round-2/repeatability/L3-20261029/`.

## Результати

| Приклад | Початковий dev | Повтор1 | Повтор2 | Повтор3 |
|---|---|---|---|---|
| `nude-clean` | true / valid | true / valid | true / valid | true / valid |
| `nude-issue` | false / invalid | false / invalid | false / invalid | false / invalid |
| `intimacy-clean` | true / valid | true / valid | true / valid | true / valid |
| `intimacy-issue` | false / invalid | false / invalid | false / invalid | false / invalid |

**Помилка відтворилася на обох тих самих проблемних текстах у всіх трьох нових повторах.** Разом із початковим dev кожен із них має4/4 відповідей з `complete=false`; чисті контролі —4/4 з `complete=true`. У новій серії6/12 valid і6/12 invalid. Це вибіркова діагностика відомих помилок із контролями, а не оцінка частоти помилок на всьому наборі.

У всіх шести невалідних відповідях модель описує відповідну реальну суперечність: 14:00 проти11:00 або перше знайомство сьогодні проти минулого шлюбу. Тексти пояснень іноді відрізняються; відтворюється саме помилковий прапорець завершення, а не обов’язково дослівна відповідь.

Це **не обрізання виходу чи витрати на reasoning**: усі12 мають `finish_reason=stop`, фактичний reasoning0, output46–160 токенів при ліміті4096. Явних content refusals, HTTP-помилок або timeout немає. Сумарний час генерацій218,124с, p50 18,453с; усі виклики коротші60с. Після серії власний інстанс вивантажено, GPU повернуто в порожній початковий стан. Платних API-викликів0; хмарний бюджет не змінився.

Машинні агрегати, SHA запитів/відповідей та порядок: [L3-repeatability-summary.json](round2/L3-repeatability-summary.json). Сирі відповіді й reasoning traces не публікуються. Початковий `dev-summary.json` лишається незмінним: там досі8 початкових викликів L3, а не20.

## Інтерпретація та наступне рішення

У цих чотирьох текстах патерн стабільний. Можливе пояснення — L3 у конкретних проблемних прикладах трактує `complete` як узгодженість тексту, хоча спільний промпт явно визначає його як завершеність перевірки. Це **гіпотеза**, не встановлена внутрішня причина; у початковому `letter-issue` модель повертала `complete=true`, тому універсального правила «будь-яка суперечність → false» немає.

Три повтори не доводять неможливість іншого результату, не дозволяють приписати збій цензурі та не визначають ефект abliteration. Підміна `false` на `true` змінила б контракт і приховала вимірюваний недолік, тому не виконувалася.

Допуск усіх моделей із чесним обліком invalid або окрема зміна спільного промпту з повторною кваліфікацією до freeze досі потребують рішення власника. Нових викликів для зміни промпту цей експеримент не дозволяє. Holdout залишається невикликаним; сумарний лічильник дослідження після цього етапу76 inference:64 початкового dev +12 діагностичних.

Зміни документаційні, без змін продукту, його SPEC.MD, ролей чи інструкцій UA/EN.

Подальша перевірка гіпотези про формулювання промпту: [окремий дослід36 викликів](2026-10-29-L3-complete-prompt-probe.md). Ці результати не входять у початкові12 повторів.
