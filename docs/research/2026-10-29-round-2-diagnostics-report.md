## 1. Провенанс speculative decoding

Для кожної з шести моделей перевірено dev load, final-load-only та 18 quality load sessions — 20 збережених профілів на модель. Для кожної моделі знайдено лише один набір speculative settings. Усі пари L1/L2 та L3/L4 мають однакові налаштування всередині пари.

| Конфігурації | MTP | Simple draft | Зовнішня draft-модель | Max / min draft tokens | Min continue probability |
| --- | --- | --- | --- | --- | --- |
| L1, L2 | true | false | порожній рядок | 3 / 0 | 0 |
| L3, L4, L5, L6 | false | false | порожній рядок | 3 / 0 | 0 |

Збережені metadata позначають MTP; підстав називати окрему зовнішню draft-модель немає. Конкретну внутрішню реалізацію/голову runtime ці записи не ідентифікують. Модель не перезавантажувалася, API не викликався.

| Модель | Dev: позитивний draft counter / викликів | Quality: позитивний draft counter / викликів | Dev: draft / accepted tokens | Quality: draft / accepted tokens |
| --- | --- | --- | --- | --- |
| L1 | 8/8 | 144/144 | 1248 / 526 | 26073 / 10903 |
| L2 | 8/8 | 144/144 | 1371 / 530 | 30150 / 16274 |
| L3–L6, кожна | counter відсутній у 8/8 | counter відсутній у 144/144 | невідомо | невідомо |

Відсутній counter не перетворено на виміряний нуль. Різні суми запропонованих/прийнятих токенів L1/L2 не означають різні налаштування draft. Парна stop-умова за доступними load records не спрацювала; це не доказ того, що speculative decoding не впливає на результати.
