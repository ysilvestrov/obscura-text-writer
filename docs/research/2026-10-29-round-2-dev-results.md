Дизайн: [28.10](2026-10-28-local-planner-round-2-plan.md), зміна хмарних учасників і бюджет: [29.10](2026-10-29-round-2-cloud-amendment.md). Машинні агрегати: [dev-summary.json](round2/dev-summary.json). Ваги/команди/залежності: [weights-provenance.json](round2/weights-provenance.json).

Подальша окрема діагностика: [12 повторних викликів L3](2026-10-29-L3-dev-repeatability.md). Наведені нижче64 виклики та8 відповідей на модель — початковий dev; діагностика їх не перезаписує.

## Виконане

Усі шість локальних артефактів готові й перевірені SHA-256. L1–L4 самостійно конвертовано з pinned safetensors у F16, потім Q4_K_M без imatrix одним llama.cpp commit `8642541b255bfb5dc39cd351a178be09013a55d6` / b11960. MamayLM конвертується, Lapa не знадобилася. L5 — існуючий файл першого раунду з тим самим SHA; його початковий HF revision невідомий. L6 — готова Unsloth Q4_K_M з pinned revision і SHA.

Windows заблокував DLL офіційного квантизатора; захист не змінювали. За прямим рішенням власника CPU-квантизацію перенесено в установлену Ubuntu WSL2, з portable CMake 4.4.5 / GNU 15.2.0. Python-конвертація лишилася в ізольованому Windows-середовищі. Це відхилення платформи від початкового очікування, однакове для обох пар. Вбудований Git discovery відключено, щоб build не записав commit цього проєкту замість llama.cpp.

Перша спроба L6 download через HF Hub 2.3.0 завершилася ReadError; клієнт видалив process-unique partial. Окремий повтор завантаження через isolated HF 0.36.2 з persistent resume успішний. Це завантаження ваг, а не повтор модельної відповіді. Секрети не публікуються; ваги та сирі відповіді ignored.

Усього **64 inference**, із них 16 платних. Незалежні load/unload перевірки не рахуються як inference. L1/L3/L6 спочатку зупинено на першій невалідній відповіді; після перегляду власник явно погодив завершити ще не виконані старі приклади. Попередні відповіді взято з checkpoint, **не повторено й не відремонтовано**. Ні prompt, ні schema, ні holdout не змінювалися.

Помилки:

- L1 `intimacy-issue`: правильна за змістом суперечність, але `source_refs=["S1","S1"]`; дублі не видалялися валідатором.
- L3 `nude-issue` і `intimacy-issue`: знайдено фактичні суперечності, але `complete=false`. Неповна відповідь не є успіхом, попри зміст зауваження.
- L6 `nude-clean`: хибне зауваження про повторне узгодження меж зйомки, без `source_refs`; відповідь невалідна й не оголошується content refusal.

Ці числа не є фінальними FP/FN: формальна валідність відділена від правильності. Обидва хмарні орієнтири в цій короткій dev-серії знайшли чотири очевидні суперечності й не дали зауважень до чотирьох clean. Основний holdout складніший; переносити 8/8 на нього не можна. L5 теж може пройти простий dev — негативний контроль оцінюватиметься на повному наборі.

## Фактичні ресурси

- RTX 5070 Laptop, 8151 MiB, driver 582.05; Windows, 32 GB RAM. Вибраний Bionic runtime — **CUDA12 llama.cpp 2.66.0**, Bionic **1.1.8 build10**. Commit runtime не експонується; SHA ключових DLL у dev-summary. Це окремий runtime від WSL-квантизатора.
- Локальний запит: temp 0,1, max output4096, reasoning none, protocol3 `check/current_consistency`, result cap4096 / max concerns3. Фактичний `reasoning_tokens=0` у всіх 48 локальних відповідях, reasoning text порожній.
- Запитаний load: 128K для L1/L2/L5/L6, 32K для L3/L4; batch512, Flash Attention і KV GPU. Короткі dev не доводять роботу довгого 128K input чи бонусу далекої залежності.
- У початковому AUTO-профілі engine log дав L3=39 і L4=38 GPU layers. Після dev налаштовано **лише власні дослідницькі L3/L4**: AUTO off, UI GPU38, context32768. Окремий load-only контроль показав engine `n_gpu_layers=39` **для обох**, VRAM7752 MiB. Число в UI та engine log не підміняємо одне одним; доказ тут — рівність фактичної конфігурації. Початкові dev timing не є парним порівнянням швидкодії, основний timing буде з вирівняним профілем.
- Balanced power scheme; після dev ноутбук підключений до AC, заряд96%. Живлення не логувалося безперервно; точні timing-висновки потребують окремого контрольованого проходу.
- Після серій і парного load-only smoke усі власні інстанси вивантажено. Початковий стан GPU був порожній. Власні hardlinks `round2-r28l` залишаються для експерименту; це ще не фінальне очищення бібліотеки. Оригінальні файли/моделі та product roles не змінено.

Офіційний SDK1.5.0 перевірено в окремому середовищі: Bionic не надає сумісний `/llm` WebSocket endpoint. Для ручного GPU-профілю використано UI; решта load/unload та генерація — документовані native REST/OpenAI-compatible API. Залежності продукту не змінювалися.

## Вартість та рішення до freeze

16 хмарних dev-викликів: **$0,0054546**, розраховано за usage й тарифами Standard; це не квитанція білінгу. Залишок спільного погодженого ліміту — **$9,9945454**. Google не повернув окремого thoughts count: reasoning telemetry лишається unknown, а сукупну оплачувану генерацію можна розрахувати з `totalTokenCount−promptTokenCount`. Ці поля не підміняються одне одним.

Власник погодив окреме порівняння трьох метрик для L5: одна з L1–L4 має бути не гіршою одночасно за FP, пропущеними фактами та валідністю й кращою хоча б в одному. Нічия/компроміс між метриками не дає однозначного висновку; довільної суми балів немає. Код перевіряє цей критерій лише на повних однакових знаменниках144/60/84.

**До freeze ще потрібні:** рішення щодо включення моделей із invalid dev, остаточний план сліпої розмітки/спільної 20% TP-панелі, freeze/prepare/quality/timing команди з перевіркою hashes і бюджету, заморожений manifest та прогноз ресурсів. Старші Argon/Opus не викликалися. Повний round2 не завершений; жодного висновку про переможця чи ефект abliteration поки немає.
