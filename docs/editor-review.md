# Промпти та перегляд редакторських правок

## Редактура з переглядом змін

У налаштуваннях редактора виберіть **«Редактура з переглядом змін»**, поверніть стандартний промпт або явно призначте власний контракт `edit/diff/1`, збережіть роль. Цей режим надсилає тільки чернетку й промпт, повертає звичайну прозу без JSON Schema та за наявності змін завжди чекає вашого рішення. Старі режими лишаються доступними.

Експериментальний профіль Venice: `abliteration-abliterated-model-large-v2`, температура 0,2, Reasoning effort `low`, прапорець «Вимкнути thinking» вимкнений, резерв відповіді 4096 токенів. На повній тестовій сцені перевірено timeout 300 с; відповіді тривали 58 і 292 с, тому запас очікування для довших сцен може знадобитися. Контекст задавайте за каталогом моделі та фактичним preflight. Жоден профіль не вмикається автоматично.

Після «Редагувати» відкрийте **«Правки редактора»**. Початково всі прапорці порожні. Позначте потрібні зміни, натисніть **«Переглянути вибраний текст»**, перевірте зібраний результат і натисніть **«Застосувати вибрані правки»**. Після зміни прапорців перегляд треба оновити. Якщо модель запропонувала фактичні зміни, порожній авторський вибір явно приймає початкову чернетку. Якщо сама модель не запропонувала змін (порожній список, лише заміни без змін або ідентичний текст у diff), прийняття недоступне: показується «Редактор не запропонував змін», без нової версії й автоматичного повтору. Це не підтверджує відсутності помилок у чернетці. Далі використайте **«Продовжити після прийнятого етапу»** для зупиненого workflow.

Кожна правка показує речення у двох рядках: «Було» з червоним закресленим оригіналом і «Стало» із зеленим підкресленим виправленням. Незмінні частини залишаються звичайного кольору. Це працює для точкових правок і програмного diff. Програма показує точні зміни й контекст, але не знає, чи правильно модель витлумачила жест, образ або подію. Зміни чисел, заперечень, переносів і великої частини тексту позначаються попередженнями; це ручний режим. Старий режим модельних точкових правок зберігає свої строгі заборони.

Зміна чернетки або стороннє перепризначення прози блокує старе прийняття. Автоматичного повтору виклику немає; сирий кандидат та історія зберігаються. Межі порівняння: 80000 символів кожного тексту, 12000 одиниць порівняння, 400 авторських одиниць змін. Текст при перевищенні не обрізається.

## Необов’язкова класифікація

Це окремий платний виклик для cloud-провайдера; сам diff і його прийняття без нього працюють. У налаштуваннях редактора розгорніть **«Необов’язковий класифікатор змін»**, заповніть JSON або скористайтеся кнопкою прикладу, збережіть роль. Порожнє поле вимикає профіль. Перед cloud-викликом потрібен явний бюджет оповідання й чинний тариф.

Приклад конфігурації, не підтвердження літературної надійності моделі:

```json
{
  "provider": {
    "provider": "venice",
    "model": "qwen-3-8-27b",
    "key_env": "VENICE_API_KEY",
    "timeout": 300,
    "response_mode": "json_schema",
    "include_usage": true,
    "venice_disable_thinking": true
  },
  "context_tokens": 32768,
  "max_output_tokens": 4096,
  "max_input_chars": 80000,
  "temperature": 0.2
}
```

Значення ключа зберігайте в `.env`; JSON містить лише ім’я змінної. Для іншої моделі перевірте контекст, вихідний резерв і підтримку схеми; для іншого провайдера змініть provider/model/key_env. Локальний профіль використовує provider=local і loopback API. Кнопка спільної моделі для чотирьох ролей цей окремий профіль не змінює.

У панелі правок натисніть **«Класифікувати зміни»**. Запуск з’явиться у звичайній черзі; його можна скасувати, а після завершення — оновити перегляд. Поради позначені як модельні, можуть містити хибні категорії й пояснення та не вмикають прапорці прийняття. Помилка класифікації не забирає доступу до diff. Явна відмова блокує цю модель класифікатора для оповідання; технічний збій — ні. При відмові оберіть іншу модель або продовжуйте ручний перегляд без класифікації.

## Налаштування промпту

У налаштуваннях кожної ролі показано потрібний контракт: етап, режим і версію схеми. Стандартний промпт вибирається автоматично. Власний текст під час збереження призначається вибраному режиму.

Старий власний промпт без призначення не запускається. Перевірте його формат відповіді, поставте прапорець «Я адаптував власний промпт…» і збережіть роль. Створиться нова версія; попередня залишиться в історії. Для підготовки структури планувальника є окреме підтвердження `prepare/blueprint/1`.

Після зміни режиму, наприклад із повної редактури на точкові правки, адаптуйте власний промпт і явно призначте його або натисніть «Повернути стандартний промпт» та збережіть. Контракт перевіряє формат призначення, але не розуміє довільні інструкції всередині тексту.

## Точкова редактура

У ролі редактора виберіть «Точкові мовні правки». Застосування:

- **Автоматично після перевірки** — типово: усі допустимі правки стають новою прозою, workflow іде далі.
- **Спочатку перегляд автором** — workflow чекає; поточна проза не змінюється.

У робочому просторі сцени відкрийте «Правки редактора», виберіть пропозицію та позначте потрібні заміни. «Застосувати вибрані правки» створює нову версію. Можна зняти всі прапорці й зберегти оригінал без цих змін. Автоматичний вибір також можна переглянути, доки чернетка, залежності й поточна проза відповідають цій пропозиції. Це не викликає модель.

Після ручного прийняття зупиненого етапу використайте **«Продовжити після прийнятого етапу»**. Редактор повторно не викликається. Пам’ять та оцінювання виконуються наступними етапами за чинними налаштуваннями. Незбережені правки спершу треба зберегти; зміни джерел або стороння заміна прози блокують стару пропозицію замість перезапису нового тексту.

## Мовні попередження

В історії версій виберіть чернетку або прозу й натисніть «Перевірити мову вибраної версії». Перевіряється саме збережена версія, а не незбережений буфер. Аналіз локальний і безкоштовний, текст не змінюється.

Правила знаходять окремі літери іншої абетки, змішані абетки в слові, повтори сусідніх слів, можливий дефіс замість тире в репліці та конкретні помилки з пілотів. Цитата або художній прийом можуть дати навмисний збіг. Відсутність попереджень не означає безпомилковості граматики, імен, часу оповіді чи сюжету. Доросла тема сама по собі не є мовною помилкою.

Контрольні приклади версійовані. Зміна їхнього набору інвалідовує старий допуск Evaluator; режим «лише звіт» лишається доступним без твердження про калібровану якість.

## Якщо редактор не завершується або повертає мало правок

Вхідний контекст і резерв відповіді — різні ліміти. Якщо `finish_reason=length`, `content` порожній, а usage показує весь completion у reasoning, модель витратила резерв на внутрішні міркування. Збільшення контекстного вікна цього не виправляє. Повідомлення називає цю причину; автоматичного повтору немає.

Підтримка вимкнення reasoning і JSON Schema залежить від конкретної моделі та провайдера. Перевіряйте фактичний usage: прапорець вимкнення сам по собі не доводить відсутності reasoning. Не збільшуйте вихідний резерв без контролю бюджету.

## Кілька проходів редактури

У робочій області виберіть максимум проходів (типово 5, від 1 до 10) і натисніть **«Редагувати»**. Підтримуються patches, diff і prose з їхніми налаштованими промптами. Джерело — поточна проза; якщо її ще немає — чернетка. Підтвердження показує лише редактора й максимальну кількість спроб. Для хмари діють бюджет оповідання та необов’язковий ліміт цього запуску.

Редактор працює на окремих копіях: кожен наступний виклик бачить попередній кандидат. Коли змін більше немає, досягнуто ліміту або текст починає повторюватися, цикл зупиняється. Відкрийте «Правки редактора»: один спільний diff порівнює початковий текст і фінальний кандидат. Позначте правки, перегляньте вибраний текст і прийміть результат. Це завершує цикл без нового виклику; вихідна чернетка збережена. У «Уся сцена» та «Пройти решту» діє той самий ліміт і один перегляд на кожну сцену. Джерело там — поточна чернетка після письменника. Після прийняття натисніть «Продовжити після прийнятого етапу»: workflow перейде до пам’яті та наступних сцен без повторної редактури. Окрема кнопка «Редагувати» завершується після прийняття; пам’ять, оцінювач і класифікація для неї запускаються окремо.

Проміжні робочі тексти зберігаються як draft в історії, але автоматично не вибираються. Пауза діє між проходами; скасування не стирає історію. Після помилки/відмови/браку бюджету автоматичного повтору немає: можна переглянути проміжні версії або явно повторити невдалу спробу в залишку ліміту. Ліміт рахує всі спроби, зокрема невдалі. Після перезапуску невизначений виклик потребує явного повтору; підтверджений результат не генерується вдруге. Зміна вихідних матеріалів зупиняє цикл, щоб не замінити авторські правки.

Якщо перший прохід не знайшов змін, прийняття не пропонується. Комплексний workflow продовжиться лише за наявності вже вибраної актуальної прози з ідентичним текстом; інакше зупиниться перед пам’яттю з поясненням. Старі збережені запуски та API-запити без edit_workflow=loop зберігають одиночну редактуру.


## Прийняття речення цілком

Кожна група має один прапорець для всіх змін одного вихідного речення цієї пропозиції. «Було / Стало» показує речення повністю; окремі заміни підсвічені, незмінні слова між ними не закреслюються. Це стосується також уже збережених пропозицій та спільного diff багатопрохідної редактури, без повторної генерації.

Якщо старе рішення містило частковий вибір такого речення, прапорець невизначений: оберіть групу цілком або відхиліть її, потім перегляньте зібраний текст. Старе рішення й проза не змінюються від відкриття панелі. Через API також не можна прийняти лише частину групи. Розбиття речень евристичне; первинні зміни через кілька речень можуть утворити ширшу нероздільну групу.
