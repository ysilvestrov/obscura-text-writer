# Збирання пакета для Microsoft Store

Документ для того, хто збирає пакет. Користувачам застосунку він не потрібен. Вимоги — у [SPEC.MD](../SPEC.MD), `PACKAGING-001`.

## Що потрібно

- Windows 10 версії 2004 або новіша, x64.
- Робоча копія репозиторію з віртуальним середовищем і залежностями: `pip install -e ".[web,publication,local-tokens,desktop,build]"`.
- `makeappx.exe`. Він є в Windows SDK і в меншому пакеті `Microsoft.Windows.SDK.BuildTools` з nuget.org (тека `bin\<версія>\x64`). Шлях передається аргументом `--makeappx` або змінною середовища `MAKEAPPX`. Для збирання без пакета (`--skip-msix`) він не потрібен.

Скрипт нічого не завантажує й не встановлює.

## Команда

```powershell
./.venv/Scripts/python.exe scripts/build_store.py `
  --out C:\tmp\obscura-build `
  --report-url https://<адреса для скарг> `
  --support-url https://<адреса подяки> `
  --waitlist-url https://<адреса запису на платну версію> `
  --identity-name <Name з Partner Center> `
  --publisher "<Publisher з Partner Center>" `
  --publisher-display-name "<назва видавця>" `
  --makeappx <шлях до makeappx.exe>
```

- `--out` — порожня або відсутня тека. Скрипт нічого не пише й не видаляє поза нею.
- `--report-url` обов’язковий для видання `store`; інші адреси можна не задавати.
- Ідентичність пакета (`--identity-name`, `--publisher`, `--publisher-display-name`) дає Partner Center після резервування назви застосунку. Для пробного збирання підійдуть будь-які значення.
- `--skip-msix` зупиняється після самоперевірки й не потребує ні ідентичності, ні `makeappx`.

У теці результату з’являються: `Obscura\` (заморожений застосунок), `self-check.json`, `pyinstaller.log`, а без `--skip-msix` ще `msix-layout\`, `makeappx.log` і `Obscura-<версія>.msix`.

## Що перевіряє збирання

Після заморожування скрипт запускає `Obscura.exe --self-check` і вважає збірку придатною лише за зеленим звітом:

| Перевірка | Що доводить |
|---|---|
| `tls_context` | застосунок може створити захищене з’єднання, тобто дістатися хмарного провайдера |
| `edition_marker` | позначка видання читається; скрипт окремо звіряє, що видання саме те, яке збирали |
| `package_data` | на місці переклади, шаблони, міграції бази, промпти й шрифти |
| `key_store` | доступне сховище облікових даних Windows |
| `tray` | бібліотека значка в треї імпортується |
| `database` | створюється база чинної схеми |
| `licenses` | поруч із виконуваним файлом є `THIRD-PARTY-NOTICES.txt` |

Збирання також зупиняється, якщо для якоїсь залежності немає тексту ліцензії.

## Інтерпретатор Python

Скрипт працює на будь-якому CPython 3.12. Якщо стандартна бібліотека інтерпретатора потребує додаткових файлів, яких PyInstaller не бере (так поводиться Python із комплекту Codex: його `ssl.py` читає `codex-rejected-cas.pem`), скрипт кладе їх у збірку, а перевірка `tls_context` підтверджує результат. Пакет для публікації в Store слід збирати на офіційному CPython з python.org.

## Ліцензії компонентів

`THIRD-PARTY-NOTICES.txt` збирається з метаданих встановлених залежностей. Бібліотека `pystray` має ліцензію LGPL-3.0, тому лежить у збірці окремими файлами (`_internal\pystray\`), які користувач може замінити.

## Перевірка встановлення

Пакет зі Store підписує Microsoft. Щоб встановити власноруч зібраний пакет, його треба підписати сертифікатом, якому довіряє система; процедура — у [ручних перевірках](verification/manual.md#store-package-install). Це зміна системних налаштувань безпеки, тому її виконує власник машини.

## Чого тут немає

Подання в Store, справжні значки пакета, автоматичне збирання в CI.
