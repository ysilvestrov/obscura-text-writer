# Картка публікації

У робочому просторі твору відкрийте **«Картка публікації»** у правій панелі над кнопкою **«Опублікувати»**. Вона доступна й до створення першої сцени. Порожні необов’язкові відомості дозволено зберігати. Експорт MD/TXT/FB2/EPUB/PDF уже доступний; «Опублікувати» створює локальний файл. Для FB2 збережіть автора й хоча б один жанр.

Назва для публікації може відрізнятися від робочої. Порожня назва використовує поточну назву твору. Мова типово `uk`; підтримуються структурні мовні теги, наприклад `en` чи `uk-UA`, без перевірки реєстру мов. Анотація — текст для читача. Оберіть до 10 жанрів, ключові слова введіть окремими рядками (до 30, до 100 символів кожне).

Розгорніть **«Спільний довідник авторів і псевдонімів»**, додайте публічний підпис. Потім оберіть його в основній частині й натисніть **«Додати автора»**. Кнопки «Вище»/«Нижче» визначають порядок. Довідник спільний для всіх творів; справжнє ім’я й псевдонім — незалежні записи. Перейменування видно в картках, а вже сформовані експорти не змінюються. Архівація прибирає запис з нового вибору, зберігає посилання в наявних творах і допускає відновлення.

У **«Додаткових відомостях»**: цикл/номер, дата публікації, видавець, ISBN, текст прав/ліцензії, перекладачі й мова оригіналу. Номер потребує назви циклу. Дата — календарна, ISBN перевіряється за контрольною сумою; невідомі відомості не заповнюються автоматично.

Обкладинка — один PNG або JPEG до **10 MiB / 20 мільйонів пікселів**. Завантаження показує preview, але **потрібно «Зберегти картку»**, щоб застосувати його разом з іншими правками. «Прибрати з картки» також потребує збереження. Старі файли не стираються. Зображення нормалізується без зайвих EXIF/GPS, орієнтація враховується, кадрування немає. Залежність для upload: `python -m pip install -e ".[web,publication]"`; без Pillow метадані й MD/TXT залишаються доступними, upload пояснює відсутній пакет.

При конфлікті двох вкладок правки лишаються у формі. «Оновити дані» запитає, чи відкинути незбережене. Помилка upload зберігає попередню обкладинку й інші поля. Зміни картки не роблять прозу, пам’ять чи оцінки застарілими.

**«Запропонувати»** використовує налаштування **планувальника**, один виклик за всією готовою актуальною прозою твору. Потрібна проза кожної активної сцени. Для платного API задайте бюджет оповідання; тариф і доступний залишок перевірятимуться також перед відправленням. Якщо контекст замалий, збільште context_tokens/max_input_chars відповідно до можливостей моделі або оберіть іншу модель: текст не обрізається й не ділиться автоматично.

Результат розгортається під кнопкою: лише порожні анотація, жанри й ключові слова (успадкована назва вже заповнена). Натисніть **«Заповнити порожні поля»**, перегляньте/відредагуйте форму й **«Зберегти картку»**. Поля, які ви змінювали вручну, не підмінюються. Перед іншою пропозицією збережіть або відкиньте попередню через «Оновити дані». Якщо змінилися проза, назва чи порядок сцен, Save відхилить застарілу пропозицію без втрати форми.

Помилка показує реальну доступну причину, історія зберігає спроби. Порожній/невірний JSON, відмова чи технічна помилка не пропонуються для прийняття. «Скасувати» завершує активний або зупинений запуск; після перезапуску застосунку перервана операція сама не повторюється. Перезавантаження сторінки знаходить наявну історію й поточний запуск.

Якщо частина допустимих полів порожня, коректні непорожні пропозиції залишаються доступними. Попередження називає поля без пропозиції; їх можна заповнити вручну. Наприклад, порожні жанри не відкидають анотацію й ключові слова, але перед FB2 експортом жанр треба обрати. Порожнє відоме поле, якого не запитували (наприклад, genres: [] при вже обраному жанрі), пропускається з попередженням без зміни картки. Непорожній невідомий жанр, непорожнє незапитане поле, будь-яке невідоме поле або повністю порожня пропозиція залишаються помилкою. Автоматичного повтору чи заповнення картки немає; старі невдалі спроби не переписуються.

Після оновлення коду потрібен звичайний перезапуск застосунку: при відкритті каталогу даних міграція 003 переводить схему 2→3. Старі payload і exports не переписуються. Перед оновленням робочого каталогу рекомендовано чинну процедуру холодного резервування. Read-only fsck/backup/restore підтримують обидві схеми без прихованої міграції.
