# Публікація на GitHub

## Перша публікація

Для першої публікації використовуйте свіжу перевірену копію поточних файлів,
а не історію початкового робочого репозиторію. Каталог `artifacts/public-repository`
був початковою копією; перед публікацією його потрібно оновити або створити нову.
Підготовка PR 21.10.2026 використовує `artifacts/github-pr-2026-10-21`.
Старі коміти містять авторські матеріали, внутрішні звіти та персональні
метадані. Заміна файлів у поточному checkout не очищує попередніх комітів.
Публічна копія має окремий початок історії й не містить каталогу `.git`.

Копія включає код, тести з нейтральними fixtures, конфігураційні приклади,
ліцензію, правила проєкту, специфікацію й публічні інструкції. Внутрішні
звіти, історичні плани розробки, локальні знімки й чернетки дизайну, дані, ключі,
скріншоти й старі Git-об’єкти до неї не включаються.
Публічні PRODUCT.md і DESIGN.md можна включати після перевірки: вони описують
продукт та оформлення і не повинні містити авторських творів або секретів.

1. Скопіюйте цей каталог у нове місце поза початковим репозиторієм.
2. Перегляньте його вміст і виконайте перевірки з `CONTRIBUTING.md`.
3. Створіть **порожній** GitHub-репозиторій. Його публічність не означає
   публічного розгортання застосунку.
4. У новому каталозі виконайте `git init -b main`. Налаштуйте бажані
   `user.name` та `user.email`; для приватності email можна взяти GitHub
   noreply-адресу з власних налаштувань облікового запису.
5. Перевірте `git status --short`, додайте лише перевірені файли, перегляньте
   `git diff --cached` і створіть початковий коміт.
6. Додайте URL нового репозиторію як `origin` і виконайте `git push -u origin main`.
   Не переносіть старі гілки, теги або `.git` з початкового checkout.

## Подальші зміни

### Pull request

Для наявного GitHub-репозиторію працюйте в його чистому clone на гілці
`codex/...`, перенесіть лише перевірені поточні файли й створіть PR до його
основної гілки. Не додавайте приватний локальний репозиторій як джерело Git
об’єктів і не push його історію. Для порожнього нового репозиторію спершу
потрібна мінімальна початкова main-гілка, потім гілка з кодом і PR.

Окремі логічні коміти мають відображати діагностику Evaluator, branding/UI,
публічне пакування й документацію. Якщо історію очищено через новий root,
ці пакети треба переносити без старих приватних blobs. Перед PR повторіть
тести у свіжій копії та перевірте wheel на шаблони, CSS/JS/SVG, промпти,
міграції й відсутність даних/ключів. Публікація PR не означає його merge.

Зберігайте твори поза checkout через `--data-dir`. Для експорту й резервних
копій також використовуйте приватні каталоги. `.gitignore` — захист від
випадкового додавання, а не контроль доступу. Перед кожною публікацією
перевіряйте staged diff, нові файли, скріншоти й посилання.

На GitHub перевірте налаштування secret scanning, push protection та
приватних повідомлень про вразливості. Автоматична перевірка відомих
форматів секретів не доводить відсутності всіх приватних даних.

Ліцензія коду — MIT. Вона не поширює дозвіл на приватні авторські матеріали,
які не входять до публічної копії.
