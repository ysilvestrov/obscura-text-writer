# Налаштування оцінювача

Відкрийте налаштування оповідання → **Оцінювач**. Провайдер, модель, контекст,
резерв відповіді, температура та додаткові параметри мають звичайні поля.
Зміни зберігаються кнопкою **Зберегти: Оцінювач**. Перехід до іншого розділу
зберігає незбережений буфер; Save іншої ролі його не застосовує.

Галочка увімкнення зберігає policy одразу й використовує вже збережену модель.
Для нового оцінювача спершу збережіть параметри. Вимкнення працює навіть за
невалідних полів або JSON. Зміна моделі/бюджетів потребує повного Save.
Критерії та пороги доступні в додатковій формі. Перевірене калібрування не можна
увімкнути галочкою: для зміни порогів створіть candidate. Якщо змінена конфігурація
втрачає допуск до «паузи при проблемі», явно виберіть «лише звіт» або off.

**Технічний JSON** — необов’язковий режим. Приклади нижче — API-об’єкти;
для round-trip починайте з повного об’єкта, показаного формою. Зміни в textarea
не застосовуються автоматично: натисніть Apply або Discard. До рішення звичайні
поля й Save заблоковані; негайний off лишається доступним і переживає Apply.
Fingerprints/calibrated не є редагованим доказом калібрування.

Це окремий оцінювач: комплект чотирьох моделей його автоматично не налаштовує.
Секрет лишається на сервері; форма й JSON містять лише назву env-змінної.
Наведені числа — приклади, не універсальний допуск моделі.

## Venice

Перевірена робоча конфігурація для режиму «лише звіт»:
`config/evaluator.venice.qwen-3-8.ui.example.json`. Вона виконала всі обов’язкові
оцінки першої сцени, не дала хибних зауважень на чистому контрольному тексті
й знайшла відому граматичну помилку в сцені ню. Каталог 2026-10-21 підтвердив
`uncensored=true`, контекст 262144 та JSON Schema; проте в перевіреній парі
викликів саме `prompt_json` дав повне оцінювання, а `json_schema` — not_checked.
Автоматичного fallback між режимами немає. Це початкове приймання конфігурації,
не повне калібрування. Параметри нижче можна перенести у поля; ключ не додавайте.

```json
{
  "config": {
    "provider": "venice",
    "model": "qwen-3-8-27b",
    "api_key_env": "VENICE_API_KEY",
    "max_input_chars": 100000,
    "max_output_tokens": 3000,
    "response_mode": "prompt_json",
    "temperature": 0.1,
    "timeout_seconds": 180,
    "venice_include_system_prompt": false,
    "venice_disable_thinking": true
  },
  "context_tokens": 262144,
  "policy": "report"
}
```

Підставте точний ID доступної текстової моделі з `uncensored=true`.
Для `json_schema` вона також має підтримувати `supportsResponseSchema=true`.
Якщо схема не підтримується, можна **вручну** змінити `response_mode` на
`prompt_json`; це не гарантує коректного JSON від моделі.
Перевірте, що реальний контекст моделі не менший за вказаний `context_tokens`.

`context_tokens` — сумарна місткість входу й виходу, а `max_output_tokens` —
окремий вихідний резерв. Не ставте 12000 для моделі з maxCompletionTokens=8192.
Помилка `finish_reason=length` означає незавершену відповідь, а не нестачу
вхідного контексту. У reasoning-моделей вихідний резерв також можуть витрачати
міркування; у перевіреній конфігурації Qwen thinking явно вимкнений. Режим report показує
помилки/неповне оцінювання, не надаючи некаліброваним балам права зупиняти твір.
Пам’ять R-06 до evaluator-запиту зараз не входить; її стискання не лікує

Ключ зберігається на сервері у змінній `VENICE_API_KEY`, наприклад у `.env`
каталогу запуску застосунку. **У JSON вводиться назва змінної, а не ключ.**
Офіційний `base_url` підставляється автоматично: `https://api.venice.ai/api/v1`.
Після зміни серверних змінних середовища перезапустіть застосунок.

## Локальна модель через Bionic / LM Studio

```json
{
  "config": {
    "provider": "local",
    "base_url": "http://localhost:1235/v1",
    "model": "REPLACE_WITH_EXACT_LOCAL_MODEL_ID",
    "max_input_chars": 16000,
    "max_output_tokens": 2048,
    "response_mode": "prompt_json",
    "timeout_seconds": 3600
  },
  "context_tokens": 8192,
  "policy": "report"
}
```

Вкажіть model ID із локального сервера, а не лише видиму назву картки моделі.
Порт і розмір завантаженого контексту мають відповідати Bionic/LM Studio.
Реальний API-ключ для local не потрібний. Якщо сервер і модель підтримують
JSON Schema, можна явно обрати `json_schema`.

## OpenRouter

```json
{
  "config": {
    "provider": "openrouter",
    "model": "REPLACE_WITH_EXACT_OPENROUTER_MODEL_ID",
    "api_key_env": "OPENROUTER_API_KEY",
    "max_input_chars": 40000,
    "max_output_tokens": 6000,
    "response_mode": "json_schema",
    "timeout_seconds": 180
  },
  "context_tokens": 32768,
  "policy": "report"
}
```

Ключ — у серверній змінній `OPENROUTER_API_KEY`. Офіційний endpoint
`https://openrouter.ai/api/v1` підставляється автоматично. Model ID та контекст
потрібно звірити з обраною моделлю. Налаштування не доводить її придатності
для дорослого матеріалу; це перевіряється окремим калібруванням.

## Codex CLI

```json
{
  "config": {
    "provider": "codex_cli",
    "model": null,
    "codex_command": "codex",
    "max_input_chars": 100000,
    "max_output_tokens": 6000,
    "response_mode": "json_schema",
    "timeout_seconds": 300
  },
  "context_tokens": 128000,
  "policy": "report"
}
```

Потрібен установлений і авторизований Codex CLI, доступний серверному процесу.
`model: null` використовує типову модель CLI; для каліброваного допуску
потрібен явний підтримуваний model ID. `context_tokens` треба узгодити з нею.
`base_url` та API-ключ для цього backend не використовуються.
`max_output_tokens` і `temperature` не передаються як CLI-перемикачі:
ця інтеграція не гарантує ними обмеження фактичної відповіді CLI.

## Що означають параметри

| Поле | Значення |
|---|---|
| `config.provider` | `local`, `venice`, `openrouter` або `codex_cli` |
| `config.model` | Точний ID; обов’язковий, крім типового Codex CLI |
| `config.base_url` | Адреса API; типові значення підставляються автоматично; для local можна змінити порт |
| `config.api_key_env` | Назва серверної змінної з ключем; для хмари типово VENICE_API_KEY або OPENROUTER_API_KEY |
| `config.max_input_chars` | Обов’язкова верхня межа символів **усього запиту**, включно з промптом, рубрикою, планом та текстами |
| `config.max_output_tokens` | Резерв відповіді, типово 6000; для API також передається як max_tokens |
| `context_tokens` | Загальний доступний контекст: вхід + резерв відповіді; типово 32768, мінімум 1024 |
| `config.response_mode` | `json_schema` — схема через API; `prompt_json` — схема в промпті й перевірка відповіді після виклику |
| `config.timeout_seconds` | Додатна кількість секунд; без явного значення local=3600, cloud=180, Codex=300 |
| `config.temperature` | Необов’язкове число 0–2; null не надсилає параметр до API; для Codex не передається |
| `config.venice_include_system_prompt` | Додавати типовий системний промпт Venice; типово false |
| `config.venice_disable_thinking` | Передати Venice запит на вимкнення thinking; типово false, ефект залежить від моделі |
| `policy` | Поведінка workflow, пояснена нижче |

`max_input_chars` не є кількістю токенів. Сервер окремо оцінює токени повного
запиту та додає `max_output_tokens`; сума має вміститися в `context_tokens`.
Збільшення числа в JSON не збільшує реальний контекст завантаженої моделі.
Текст приховано не обрізається. Завеликий story-case може ділитися на сценові
вікна з неповним міжсценовим покриттям; окрема завелика сцена потребує зміни
моделі/реального контексту або явного обсягу матеріалів.

## Політика й калібрування

Приклади конфігурацій не є каліброваним допуском. Починайте з report; pause_on_failure потребує власного успішного калібрування на чинному контрольному наборі. Історичні результати з іншої інсталяції не переносяться автоматично.

- `off`: оцінювач не викликається вручну чи автоматично.
- `report`: звіти й попередження; відмова або технічна помилка не блокує
  подальшу генерацію прози. Для початкового тестування обирайте цей режим.
- `pause_on_failure`: пауза при непройденому/неповному оцінюванні чи помилці.
  Потребує **зареєстрованого каліброваного профілю**; просте встановлення цього
  значення на початковому профілі буде відхилено.

Приклади навмисно не містять `profile`: сервер створить candidate-профіль.
Він дає попередні висновки зі статусом `incomplete`, навіть якщо попередній
вердикт позитивний. Це очікувана поведінка, а не збій моделі.

Якщо у вашому JSON уже є серверний `profile`, не підміняйте його
`calibrated`, fingerprints або пороги навмання. Для збереження чинного
калібрування редагуйте наявний JSON, а не замінюйте його початковим прикладом.
Зміна моделі/налаштувань/промпту/контрольного набору може скинути допуск.
Новий допуск потребує повного набору v2 та щонайменше трьох повторів,
а не лише ручного `calibrated: true`.

## Помилки й блокування після відмови

| Що бачите | Що перевірити |
|---|---|
| `missing_key` / `authentication` | Серверну змінну ключа, її назву в api_key_env та чинність ключа |
| `quota` / `rate_limit` | Баланс/квоту або обмеження частоти в провайдера; це різні причини |
| `timeout` / `connection` | Доступність API/CLI та час очікування |
| `capability` | Доступність Venice model ID, uncensored і підтримку обраного формату |
| `invalid_response` | Формат/повноту відповіді, вихідний ліміт і підтримку схеми |
| Немає успішного калібрування | Почніть із report; pause_on_failure не вмикається прапорцем у profile |
| Бракує контексту | Реальний контекст моделі, context_tokens, резерв відповіді та повний розмір входу |
| `refused` | Відмову моделі; це не літературний штраф і не технічний timeout |

Після контентної або непоясненої явної відмови цей оцінювач **заблокований для
оповідання**. Наступні вікна й сцени йому не надсилаються. Зміни промпту,
температури, off/on чи restart не скидають захист. Оберіть іншу модель явно
або вимкніть оцінювача; автоматичної заміни чи кнопки розблокування немає.
Технічні помилки такого блокування не створюють. Деталі причини доступні у
звітах оцінювання; серверне поле `block` не треба редагувати.

## Відмінність JSON для UI та CLI

**UI:** весь об’єкт із `config`, `context_tokens`, `policy` (і, за наявності,
серверним `profile`). **CLI `--config`:** лише вміст вкладеного `config`.
Файл `config/evaluator.venice.example.json` призначений для CLI, тому його
самого недостатньо для вставлення в поле UI.

Пов’язана інструкція: [запуск, резервування й dry-run калібрування](prototype-runbook.md).


Платні виклики потребують явного ліміту оповідання/CLI та чинного тарифу.
Налаштування й пояснення сум: [бюджет модельних викликів](provider-budget.md).
