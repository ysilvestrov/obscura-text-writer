# Одна редакторська правка на речення

Рішення власника 22.10.2026: усі зміни одного речення з одного виклику редактора приймаються разом.

## Requirement: EDIT-SENTENCE-GROUPS — Атомарний авторський вибір

У межах однієї обраної редакторської пропозиції (v1 patches, v2 diff або сумарний diff циклу) усі зміни одного вихідного речення SHALL утворювати одну групу прийняття. Різні пропозиції/спроби не змішуються. UI SHALL показувати один прапорець, повне «Було / Стало», незмінні частини звичайним текстом і кожний змінений фрагмент через del/ins. Частковий вибір групи SHALL відхилятися у selection-preview, сервісі публікації та storage-транзакції, без автоматичного додавання невибраних правок.

Межі речень — детермінована евристика поточного sentence context: .!?… із можливими закривальними лапками/дужками перед пробілом або кінцем, та переноси рядка. Це не повний мовний аналіз скорочень. Зміна, що сама перетинає кілька речень, не розрізається; усі перекриті нею групи об’єднуються консервативно.

## Дані, API та сумісність

Початкові proposal, індекси, fingerprint, classifier advice, raw response й історичні decisions не переписуються. Preview SHALL додати derived groups з початковими indices та текстовими before_parts/after_parts (`text`, `changed`). POST продовжує приймати selected_indices у старих індексах, але вимагає повних груп. Класифікація лишається по первинних індексах, її поради відображаються всередині групи.

Історичне часткове рішення лишається в історії. У новому UI така група невизначена до явного вибору автора, прийняття блокується до її повного вибору або відхилення. Нові й уже збережені пропозиції отримують групи при читанні, без міграції та перегенерації. Порожній вибір, коли його явно зроблено, лишається допустимим відхиленням усіх змін непорожньої пропозиції. Snapshot/CAS, guards, diff limits та multi-pass workflow незмінні.

## Перевірки

RED→GREEN: дві віддалені взаємозалежні заміни одного речення дають одну групу й правильне повне «Стало»; сусідні речення — різні групи; Unicode/CRLF/вставки/вилучення й перетини; v1/v2; частковий POST і storage bypass відхиляються; legacy decisions не змінюються; UI надсилає всі індекси одним прапорцем і показує окреме виділення змінених/незмінних частин. Статична матриця R-10, цільові й повний suite, синтетичний browser, без платних викликів.

## Виконання

Реалізовано незалежний sentence_groups, derived preview, три рівні перевірки partial selection і grouped UI з незмінними raw indices. Цільові тести 36 passed; browser один прапорець→preview→дві збережені зміни. Фінальне повне свідчення генерує verify.py у docs/STATUS.md. Самоперевірка; незалежне рев’ю цього виправлення не заявлено через сервісний ліміт reviewer.
