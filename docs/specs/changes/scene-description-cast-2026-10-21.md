# Назва й склад сцени з авторського опису

Дата: 21.10.2026. Запит власника: розпізнавати назву сцени, рядки
«Хто бере участь:» / «Персонажі:» та надавати описи лише учасників.
Виконання в поточному чаті за чинною вказівкою без додаткового погодження.

## Requirement: Детерміноване читання опису

Імпорт і ручне збереження SHALL розпізнавати заголовок Сцена N: Назва або
Сцена N. Назва, включно з Markdown heading/bold. Номер не змінює порядок.
Заголовок на початку ручного плану оновлює title. Весь авторський текст
зберігається дослівно. Відсутність заголовка не стирає ручну назву.
Обидва рядки складу сцени SHALL приймати імена або точні ID через кому/крапку
з комою, без урахування регістру імен; дублікати прибираються. Немає fuzzy
matching, транслітерації, вигаданих карток або ID. Невідомі/неоднозначні імена
не зникають з авторського плану. Немає рядка — ручний список незмінний;
явний порожній рядок — порожній список. Подвійні рядки об’єднуються.

### Scenario: Ручний план
- GIVEN план починається заголовком і має рядок учасників
- WHEN автор зберігає його з чинною ревізією
- THEN title, character_ids і plan head оновлюються в одній транзакції.

## Requirement: Картки, додані після плану

Публікація карток/blueprint SHALL повторно зіставляти рядки учасників усіх
активних сцен у тій самій транзакції. Зміни складу збільшують ревізію сцени;
legacy похідні матеріали інвалідуються, snapshot/CAS лишаються чинними.
Сцени без таких рядків зберігають ручний список. Автоматичних записів у
авторські твори під час оновлення програми немає; старі плани можна зберегти
заново для витягування назви та складу.

## Requirement: Відбір описів

Сценові brief/draft/edit SHALL отримувати лише картки з character_ids сцени,
із чинними часовими обмеженнями. Порожній склад не означає всіх персонажів.
Неструктурований raw файл лишається джерелом для підготовки карток і звірки;
цілком у сценовий запит не підставляється. Prepare може читати повні джерела.
Відомості зі сцени зазвичай задаються планом; загальна перевірена пам’ять не
перетворюється на повні описи інших персонажів.

## Приймання

Тести title/Markdown, обох labels, exact ID/name, duplicate/ambiguous/unknown,
імпорту до/після карток, atomic revision conflict, filtering/empty/raw fallback
і часових міток. Без модельних викликів та міграції SQL.


## Рішення про невідомих учасників

Власник обрав: зберігати план, блокувати генерацію до уточнення. Застосовується
до невідомих та неоднозначних імен із рядків учасників; preflight пояснює
причину, жодний inference не надсилається. Memory також перевіряє цей список.
Немає автоматичної заміни імені чи створення персонажа.

Сценове оцінювання використовує таку саму часову проєкцію карток; story-case
збирає проєкції учасників усіх оцінюваних сцен. Неотримані описи/попередження
позначаються unchecked. Snapshot Evaluator включає character_ids цільових сцен,
тому зміна складу під час запиту не публікує оцінку як актуальну. Повна картотека
без відбору та raw файл не додаються як сценовий canon документ.
