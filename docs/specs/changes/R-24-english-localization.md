# R-24 — Український та англійський вебінтерфейс

Дата: 24.10.2026. Статус: погоджено власником 24.10.2026; реалізовано за планом 2026-10-24-r24-web-localization.md.

## Мета й погоджений обсяг

Власник обрав переклад вебінтерфейсу та його повідомлень. CLI — окрема R-26; переклад промптів і вибір мови твору — R-27. Початкова UA/EN визначається за браузером; ручний вибір запам’ятовується для всіх творів у цьому браузері. Мова інтерфейсу не змінює український мовний контракт генерації.

## Поточні факти

Jinja base.html задає lang=uk; тексти містяться в шаблонах, статичних ES-модулях і Python-повідомленнях. api.js показує detail як рядок; readiness містить reason, а worker зберігає error і payload подій. Статуси й enum уже є машинними ідентифікаторами, їх не перекладати. R-20/R-21 захищають незбережені матеріали та незалежні буфери налаштувань; зміна мови не повинна перебудовувати ці форми чи повторювати GET/Save.

## Підхід і межі

Рекомендовано спільні пакетні UA/EN каталоги зі сталими ключами та параметрами, доступні серверному Jinja й клієнтському JS, без нового frontend-фреймворку. Витягувати власні UI-рядки з компонентів, а не перекладати DOM чи довільний API JSON пошуком і заміною. Новий каталог входить у wheel, завантажується лише з локального застосунку; перекладач/API моделей під час показу сторінки не потрібний.

UA/EN перемикач у спільній верхній панелі. Валідний ручний вибір у first-party cookie має перевагу; інакше — перша підтримана мова браузера (uk/en, включно з регіональними варіантами), для інших мов — uk. Сервер використовує той самий порядок із Accept-Language. Значення поза allowlist і некоректні preference дані не виконуються й не потрапляють у шляхи. Мова — локальна перевага користувача, не поле твору й не нова залежність матеріалів.

Перемикання виконується без reload. Оновлюються html.lang, title, статичні підписи, підказки, accessibility labels і поточні похідні статуси; введені значення, selection/focus, unsaved buffers, dirty/error/busy, active run і SSE subscription зберігаються. Усі наступні повідомлення використовують нову мову. Переклад не запускає моделей, не пише версій і не змінює revision.

Власні помилки та readiness/валідація/статуси мають перекладатися разом із UI. Для параметризованих повідомлень потрібні ключ і параметри, не злиття перекладених частин і не підстановка довільного рядка як HTML. Стабільні API-поля/enum, HTTP status, event seq і сирі збережені діагностичні дані зберігаються сумісними; за потреби додається окрема presentation metadata. Не зберігати локалізований текст замість машинного стану. Наявні записи не переписувати: для відомих історичних повідомлень допустима точна контрольована проєкція; невідомий історичний/провайдерський текст показувати як оригінальну діагностику з локалізованим поясненням, без втрати реальної причини.

Не перекладаються назви/плани/персонажі/чернетки/проза, значення пам’яті, завдання, коментарі, модельні відповіді, власні/стандартні промпти, модельні ID, env-назви, шляхи та файли експорту. Системні назви полів/категорій/жанрів можна локалізувати, значення авторських полів — ні. Форматування відомих чисел/дат залежить від UI locale, але збережені ISO/Decimal/JSON не змінюються; невідома usage лишається невідомою, не нулем.

## Requirement: R24-LOCALE — Початкова мова і ручний вибір

Інтерфейс SHALL підтримувати uk/en, обирати початкову за браузером та запам’ятовувати явну перевагу незалежно від твору. Зміна locale SHALL бути операцією представлення без reload і зміни матеріалів.

### Scenario: R24-LOCALE-S01 — Вибір і fallback
- GIVEN ручного вибору немає або він некоректний
- WHEN сторінку відкрито з uk-UA/en-US чи непідтриманими мовами
- THEN застосовується перша підтримана мова, інакше uk
- AND валідна явна перевага має пріоритет при наступному відкритті.

### Scenario: R24-LOCALE-S02 — Перемикання під час роботи
- GIVEN незбережені матеріали/налаштування або активний запуск
- WHEN автор перемикає UA/EN
- THEN підписи й нові повідомлення змінюються без втрати буферів, selection/dirty/busy чи повторного підключення/виклику
- AND жодні версії/revision/промпти не змінюються.

## Requirement: R24-MESSAGES — Повнота та достовірна діагностика

Власні видимі web-повідомлення SHALL мати UA/EN представлення з однаковими параметрами. Авторські дані й сирі невідомі/provider повідомлення SHALL залишатися оригінальними. Каталог SHALL перевірятися на ключі, параметри й комплектність обох мов; відсутній переклад не повинен лишати порожній напис.

### Scenario: R24-MESSAGES-S01 — Помилка та історичний запис
- GIVEN API відхилило операцію або UI показує збережену діагностику
- WHEN обрано en
- THEN власне повідомлення пояснює ту саму причину англійською, а оригінальна невідома діагностика не губиться
- AND коди, параметри, severity/refusal і технічні ліміти не підміняються перекладом.

### Scenario: R24-MESSAGES-S02 — Рукопис та безпечні параметри
- GIVEN авторський текст, JSON пам’яті, промпт або рядок із HTML-подібним вмістом
- WHEN оновлюється мова інтерфейсу
- THEN ці дані не перекладаються/нормалізуються й не виконуються як HTML
- AND числа/дати локалізуються лише для показу, без зміни збережених значень.

## План перевірок і документації

До реалізації скласти інвентар шаблонів/модулів/видимих серверних причин. Тести: вибір locale/Accept-Language/cookie/fallback; parity ключів/параметрів і контроль власних неперенесених UI-рядків; шаблони й API-представлення обома мовами; guards буферів/selection і active run при перемиканні; HTML/XSS, число/дата/unknown usage. Browser: бібліотека, імпорт, редактор усіх етапів, налаштування кожної ролі/Evaluator/бюджету, персонажі, кошик, публікація; desktop/mobile та keyboard обома мовами на нейтральному творі. Реальні модельні виклики не потрібні.

Оновити SPEC.MD, traceability з конкретними тестами, інструкцію користувача й package-data у тому самому наборі змін. SQL-міграції для переваги браузера не потрібні. CLI/промпти/мова твору лишаються поза цим пакетом. Наявність цих сценаріїв у пропозиції не є фактом виконання перевірок.

## Рішення до погодження

Ручний browser preference, автоматичний вибір початкової мови й web scope погоджені. Резервна uk для інших мов, перемикач без reload, спільний каталог та представлення історичних повідомлень — запропоновані рішення цього документа. Після погодження підготувати детальний implementation plan й виконати його в поточній сесії/папці за чинним дорученням власника, без нового погодження самого плану.
