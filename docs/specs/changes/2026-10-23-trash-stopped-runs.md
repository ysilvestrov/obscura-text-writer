# Кошик твору зі старими зупиненими запусками

Статус: реалізація виправлення повідомлення користувача 23.10.2026.

Причина: SQL guard коректно блокує незавершені запуски, але бібліотека не давала способу скасувати старі alternative/paused/interrupted/needs_review. Перегляд лише останнього запуску не розв’язував блокування.

Рішення: перед підтвердженням кошика прочитати всі запуски. Якщо залишилися лише зупинені, запропонувати явне скасування з їх кількістю, збереженням текстів/історії та без генерації. Після підтвердження послідовно скасувати їх через існуючий API; лише завершені результати дозволяють trash. Активні та невідомі стани блокують дію з конкретною інструкцією. Відмова, помилка чи незавершене скасування не запускають trash. Кнопка заблокована на час операції й відновлюється після відмови/помилки.

Сумісність: схема та серверні правила незмінні. Запити cancel/trash окремі; можливі вже скасовані запуски при наступному конфлікті ревізії/появі нового запуску. Остаточний SQL guard зберігає захист від гонки. Контракт: SPEC.MD DATA-006-S03. Перевірки: Node trash_regressions та API cancellation→trash→restore для чотирьох станів.
