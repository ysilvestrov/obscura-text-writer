# Порожня відповідь із finish_reason=stop

Погоджено прямим запитом власника 22.10.2026. Пакет виправляє діагностику, не змінює моделі, бюджети або політику повторів.

## Requirement: точна причина помилки

Потоковий шлюз SHALL відрізняти порожній content із коректним stop від відсутнього завершення. Для всіх генераційних етапів це `empty_output`, без ознаки відмови. Доступні reasoning/completion лічильники SHALL потрапляти в повідомлення; відсутні лічильники не відновлюються припущенням. Редактор SHALL не губити пояснення при збереженні спроби.

## Scenario: reasoning без фінального тексту

- GIVEN stop, відсутній content, completion_tokens=8879 і reasoning_tokens=8876
- WHEN обробляється потік
- THEN помилка називає порожню відповідь із stop та 8876 із 8879 токенів reasoning
- AND прийняття та автоматичного повтору немає.

Контракт і перевірки: PIPE-006-S02 у кореневій SPEC.MD та матриці traceability. Міграцій немає; історичні спроби незмінні. Перевірка — синтетичні SSE без зовнішніх викликів.
