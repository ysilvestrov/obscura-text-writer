# Таблиця пам’яті й авторський відбір контексту

Мета: читабельний перегляд накопиченої пам’яті без технічних ID та прапорець «Передавати далі». Запис не видаляється з доказового журналу. Зміна на межі сцени n діє лише для n+1 і далі; попередні сцени незмінні. Повторне ввімкнення можливе на будь-якій наступній межі. Автор підтвердив: оновлений claim лишається прихованим до явного ввімкнення.

Дані: Scene.memory_forwarding — необов’язковий словник claim_id→bool, defaults {}; SQL-міграції/нового VersionKind немає. Правила всіх активних попередніх сцен застосовуються за порядком; останній явний вибір для claim перемагає. Межа вибраної сцени включається лише у перегляді вихідного контексту, але не при генерації самої сцени. Новий claim має default=true; ті самі claim ID при update/retire зберігають вибір. Втрачені через нову генерацію claim ID не зіставляються за схожістю тексту.

Літературна проєкція виключає приховані claim з facts/character_states/open_threads/timeline, включно з історичними закриттями прихованої лінії; журнал/цитати/операції/catalog для моделі пам’яті незмінні. Авторські плани, канон, проза й явно вибраний хвіст попередньої сцени не цензуруються цим прапорцем. Evaluator використовує власні первинні джерела, це не глобальна заборона факту чи видалення даних.

Залежності: новий скінченний scene selector memory_projection_policy — відсортований список прихованих claim ID попередніх сцен. Він входить у brief/draft/prose_edit та author_text baseline; patches/diff/memory не читають цю проєкцію. Старі snapshots без selector для цих scope трактуються як початкове «все ввімкнено», тому поточна непорожня політика робить відповідний текст застарілим до явного прийняття. Зміна прапорців не переписує тексти/журнал і не вимагає перебудовувати memory; зміни залежного тексту позначаються через snapshot freshness. Повернення до точної початкової політики відновлює актуальність за чинними правилами.

API GET/PUT /api/scenes/{id}/memory-view: поточний memory head, rows зі змістом/категорією/сценою/доказом/вибором, ревізія сцени й fingerprint джерел/політик. PUT приймає лише зміни прапорців для відомих rows, expected_revision та fingerprint. Під BEGIN IMMEDIATE повторно перевіряються активний власник, memory head/актуальність, початковий stamp та дозволені claim ID, потім оновлюються лише правила Scene й ревізія; журнал лишається byte-for-byte. При конфлікті 409, dirty вибір у браузері не губиться. Метадані правил зберігаються в звичайному cold backup/restore разом зі Scene.

UI: вкладка «Пам’ять» типово показує таблицю «Передавати далі / Запис / Категорія / Джерело». Пошук і фільтр категорій, лічильник увімкнених/усіх; доказ у details. JSON доступний як розширений режим без втрати попереднього способу редагування. Одне явне Save для прапорців; dirty стан блокує генерацію/перемикання без звичайного попередження, async response не підміняє вибір іншої сцени. Empty/stale/error стани пояснюють причину; історична версія read-only щодо прапорців, перемикання JSON із незбереженим вибором потребує рішення відкинути.

План: RED→GREEN доменні projection/chronology/CAS/dependency тести; storage/API; UI/JS tests; SPEC та traceability; синтетичний desktop/mobile перегляд; незалежне review й повний verify; локальний коміт. Реальні API не викликаються, авторські дані не змінюються.
