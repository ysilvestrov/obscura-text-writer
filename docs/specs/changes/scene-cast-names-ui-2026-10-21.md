# Імена учасників сцени замість редактора внутрішніх ID

Дата: 21.10.2026. Запит власника — перетворити поле ID на нередагований текст
із розпізнаними іменами, оскільки склад визначає план.

## Requirement: Людинозрозумілий склад сцени

Параметри сцени SHALL показувати «Учасники сцени» як звичайний текст з іменами
карток. ID не показуються та не редагуються в цьому блоці. Підказка пояснює
рядки «Персонажі:» / «Хто бере участь:» у плані. Збереження назви/обсягу SHALL
не надсилати character_ids та не перезаписувати склад прихованим значенням.
Порожній список і відсутні картки мають зрозумілі повідомлення без raw ID.

## Requirement: Узгоджені назви

GET /api/stories/{id} SHALL додатково повертати character_names — словник
ID→ім’я чинних карток, без описів. Story/scenes/registry беруться з одного
captured view. UI читає склад вибраної сцени з останнього server view й цей
registry; показ не змінює авторський буфер або його CAS revision. Після
збереження плану/карток refresh оновлює імена та склад. Внутрішній domain,
character_ids, API явного metadata редагування та SQL2 зберігаються.

### Scenario: Збереження параметрів
- GIVEN сцена має двох учасників і автор змінює обсяг
- WHEN параметри збережені
- THEN character_ids не надсилаються цим UI та лишаються незмінними.

### Scenario: Нові картки після плану
- GIVEN старий буфер має порожній склад, а поточний серверний склад заповнений
- WHEN оновлюється story view
- THEN блок учасників показує актуальні імена без зміни тексту/ревізії буфера.
