# Початкові картки з імпортованого файла персонажів

Дата: 21.10.2026. Підтверджене рішення власника — автоматичні картки з
заголовків файла, без модельних викликів і без перезапису наявних карток.

## Причина дефекту користувацького шляху

Новий твір мав розпізнані імена учасників і source_characters, але не мав
characters_version_id. Попередній імпорт зберігав лише файл; зіставляти імена
було ні з чим. Вимога про створення карток була прихованим кроком для автора.

## Requirement: Детермінований імпорт карток

Імпорт source_characters SHALL розпізнавати Markdown-заголовки імен одного
рівня, пропускаючи загальний заголовок «Персонажі»/«Персонажи»/«Characters».
Найвищий рівень заголовків імен визначає межі карток; підзаголовки лишаються
частиною опису. Порожні описи не створюють карток. Імена очищаються від bold,
кінцевого двокрапки та пробілів, без fuzzy matching і заміни абеток.

Коли у творі ще немає published карток, сервер SHALL створити початкові v2
картки через чинний character authoring service: server IDs, origin=imported,
availability=unclassified, дослівний опис та цитата source_version_id. Публікація
має story revision CAS та повторно зіставляє учасників сцен. Початковий файл
зберігається без змін. Prepare та платні API не запускаються.

### Scenario: План імпортовано до карток
- GIVEN план називає учасників, а файл персонажів має іменні заголовки
- WHEN файл персонажів імпортується
- THEN створюються початкові картки й scene.character_ids заповнюються.

## Requirement: Сумісність і чесні повідомлення

Наявні картки SHALL не замінюватися при повторному імпорті, включно з явним
порожнім набором. Файл без придатних заголовків зберігається з повідомленням
про необхідний формат/ручні картки. Created count повертається в ImportResult.
Змішані латинські/кириличні літери в імені дають попередження, не автозаміну.
Часова неперевіреність початкових описів не приховується.

Старі твори автоматично не переписуються при запуску. Їхні початкові картки
можна створити повторним імпортом файла або чинним API authoring із перевіркою
джерела/очікуваної ревізії. Строга перевірка невідомих імен продовжує діяти.
SQL/schema2 та domain card format не змінюються.
