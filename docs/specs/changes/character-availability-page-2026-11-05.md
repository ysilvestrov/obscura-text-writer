# Окрема сторінка доступності відомостей персонажів

Статус: реалізовано за погодженим запитом власника від 05.11.2026.

## Мета й обсяг

Перенести «Доступність відомостей персонажів» із вузької правої панелі твору на окрему сторінку `/stories/{id}/characters`. Надати більше місця описам та часовим налаштуванням, зберігши чинний вигляд Obscura і всі можливості редактора.

## Підхід

Окрема серверна сторінка відповідає прямому запиту власника та чинному підходу сторінок налаштувань і публікації. Розширення правої панелі відбирає місце в рукопису, а модальне вікно не забезпечує окремої адреси; ці варіанти не обрані.

За уточненням власника посилання «Персонажі» розміщується у верхній навігації твору поруч із «Налаштуваннями» (EN: Characters). Старий блок у правій панелі прибирається. Перехід передає поточні scene/material; повернення відновлює їх через чинну перевірку маршруту. Незбережений рукопис захищається чинним механізмом навігації.

Сторінка має назву твору, заголовок, посилання повернення та верхні дії збереження, додавання персонажа й перечитування. На широкому екрані текст опису займає основну ширину, а доступність, початкова сцена та походження розміщуються поруч. На вузькому екрані поля складаються в одну колонку. Довгі описи можна редагувати в широких вертикально змінюваних полях.

Поділ за абзацами, додавання/видалення карток і відомостей, джерела, попередній перегляд для сцени та повідомлення про незбережені правки зберігаються. Перехід зі сторінки й закриття вкладки захищають незбережені правки. Помилка збереження або CAS-конфлікт не стирає буфер. Перемикання UA/EN не перебудовує авторські поля.

## Межі й техніка

Редактор відокремлюється від `editor.js`: на новій сторінці він отримує story ID від кореневого елемента, сцени/revision/cards — через чинний API персонажів. `CharacterBuffer` залишається власником стану завантаження, збереження й preview. Сторінка не підключає редактор рукопису та модулі запуску генерації.

GET/PUT `/api/stories/{id}/characters` і POST preview, модель даних, цитати, часові правила, міграції та модельні виклики не змінюються. Незбережені правки в іншій вкладці не стають міжвкладковим блокуванням; збереження й надалі захищається серверним CAS.

## Перевірки й документація

Маршрут існуючого/відсутнього твору; перехід і повернення; збереження, preview, CAS та dirty guards; порожні картки/сцени; довгий опис; UA/EN; desktop/mobile без горизонтального переповнення. Для зображень використовуються нейтральні приклади.

До завершеного набору змін входять SPEC.MD, traceability, журнал виконання, користувацькі інструкції обома мовами та фактичний результат `scripts/verify.py` у docs/STATUS.md. Після перевірок — коміт, GitHub PR і перевірена основна тека.
