# Виправлення модельного scope та діагностики пам’яті

Дата: 21.10.2026. Рішення власника: прибирати зайвий scope із попередженням.

## Відтворена причина

Завершена відповідь Venice у evidence_delta містила 9 операцій; остання
open_threads мала непорожній character_ids. Строгий validator правильно
відхиляв її, але execute_stage приховував причину за загальним повідомленням.
Read-only replay відповіді з прибраним лише цим scope пройшов усі перевірки.
Авторські дані та оригінальна спроба під час дослідження не змінювалися.

## Requirement: Обмежена нормалізація модельної відповіді

Сервер SHALL нормалізувати лише непорожній список рядків character_ids у
facts/timeline/open_threads до []. Решта даних, manual journal і строгі
validators незмінні. Застосовується до add/update/retire, але не змінює їхніх
правил чи відомості попереднього журналу. Після нормалізації залишаються
обов’язковими schema/category/claim/evidence/source/prefix/scope перевірки.

### Scenario: Успішне виправлення
- GIVEN модель додала scope до open_threads
- WHEN після вилучення scope всі перевірки успішні
- THEN пам’ять публікується, raw partial незмінний, memory_warnings збережено
- AND run.warning показує попередження після reload.

## Requirement: Безпечна конкретна причина

Для помилок пам’яті SHALL показувати дозволену причину та номер операції/поле
або JSON-координати. Не показувати сирий ValidationError/input/невідомі ключі
чи довільний текст винятку. Невідомі помилки лишаються загальними; raw partial
зберігається у штатному сховищі без автоматичних повторів.

### Scenario: Невідомий evidence_id
- GIVEN модельна відповідь не має відповідного фрагмента прози
- WHEN перевірка відхиляє її
- THEN UI отримує конкретну причину, пам’ять не публікується.

## Реалізація та приймання

memory/journal.py — модельна нормалізація; memory/diagnostics.py — безпечні
причини; generation/stages.py — стійкі warnings і помилка; worker.py — run.warning.
Міграцій SQL/API/UI не потрібно. Десять synthetic regression tests: scope трьох
категорій, захист доказів/персонажів, приватність, точна помилка та reload warning.
Платних викликів немає. Старі attempts не переписуються заднім числом.
