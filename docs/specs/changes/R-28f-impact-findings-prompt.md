# R-28f — Тільки необхідні виправлення у new_findings

Погоджено автором: уточнити wire2 prompt після reduce_check/no_impact з трьома описовими спостереженнями у new_findings. Модель SHALL повертати новий finding лише для конкретної потрібної зміни target через old→new передумови, з поясненням суперечності та що виправити. Узгодженість, переказ, цитування й необов’язкові стильові поради належать summary, не findings. no_impact вимагає порожнього new_findings і відсутності inherited findings; changes_required потребує нових або успадкованих findings. uncertain без нових findings, але не стирає успадковані. Фінальна самоперевірка перед JSON; автоматичного семантичного ремонту немає.

План: змінити тільки impact_part_uk_v2.txt; актуалізувати SPEC та UA/EN guide; запустити існуючі native/proof/legacy та budget тести через verify.py; один нейтральний локальний контроль нового system prompt для повторної кваліфікації того самого tokenizer/template. Новий профіль явно активувати після точного збігу usage, зберегти стару прив’язку для frozen run. Промпт читається з ресурсу під час кожного нового preview, перезапуск сервера не потрібен; повний book run не запускати. Старі manifests/API/raw/results не переписуються; новий prompt доступний тільки новим preview/run. SQL/wire schema без змін.

Межі перевірки: тести доводять передачу/відтворення контракту, не літературну якість. Нейтральний контроль не гарантує поведінку на всіх текстах. Без нового qualified binding працює conservative fallback; його не видавати за збережений точний counter.

Реалізація: prompt/SPEC/UA+EN guide оновлено; verify60PASS/source_changed=false, один neutral control stop/no_impact/no findings, tokenizer1219=usage1219, нову прив’язку активовано зі збереженням старої. Після перевірки plan_chunks підтверджено: ресурс читається заново для нового preview, restart не потрібен і не виконувався. Генерація книги не запускалась.
