# R-14a — План вимірювання сховища

> Виконання: superpowers:executing-plans, у цьому чаті. Власник прямо доручив виконати лише вимірювання; оптимізація потребує наступного рішення.

**Мета:** відділити фактичні SQL-вузькі місця від вартості доменного читання.

**Архітектура:** одноразовий probe в artifacts, нові синтетичні бази, чинний Repository без змін. Жодних платних API або читання робочих творів.

**Стек:** Python, SQLite, perf_counter, cProfile, statistics.

**Специфікація:** [R-14a](../../specs/changes/R-14-storage-measurements.md).

## Обмеження та ризики перевірки

- Прогрітий filesystem cache не називати холодним диском.
- Не підміняти API latency часом SQL без десеріалізації.
- Stress-набір не вважати доведеною поточною потребою.
- Trace/profiler виконувати окремо від timings.
- Перевірити FK, hashes, розміри й незмінність seeded даних; не використовувати робочий data-dir.
