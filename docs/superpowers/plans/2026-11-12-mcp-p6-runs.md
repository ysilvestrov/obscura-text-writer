# MCP, пакет 6, PR 2: запуски з чату — план реалізації

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** у творі «пише Obscura» чат запускає один етап сцени або пропозицію картки публікації після перегляду, читає стан і скасовує власний запуск; усе інше керування запусками від моста сервер відхиляє.

**Architecture:** сервер перевіряє запити з позначкою `X-Obscura-Client: mcp` (`web/bridge_marker.py`, PR 1) у маршрутах запусків і позначає запуск моста `Run.origin='mcp'`. Міст отримує `start_run` (перегляд через readiness + budget, запуск із `confirm=true` і клієнтським `request_id`) і `get_run` (стан, спроби, пропозиції; `cancel=true` скасовує власний).

**Tech Stack:** Python 3.12, FastAPI, httpx, `mcp==2.3.0`, pytest.

**Spec:** `docs/superpowers/specs/2026-11/2026-11-12-mcp-p6-obscura-writes-design.md` (затверджено 2026-11-12; перегляд перед запуском обов'язковий).

## Global Constraints

- `Run.origin: Literal['mcp'] | None = None`; без міграції.
- Відмови (запит із позначкою): режим `chat` + `POST /api/runs` → 409 «Твір у режимі «пише чат»: напишіть текст самі (get_stage_task, save_draft)»; `mode` поза `{stage, publication_suggest}`, `pause`, `resume`, `cancel-request`, `continue-after-acceptance`, `prepare`, класифікація правок і оцінювання → 403 «Цю дію із запуском виконує лише автор в Obscura»; `cancel` запуску з `origin!='mcp'` → 403 той самий текст.
- Текст відмови записів у режимі `obscura` повертається до специфікації: «Твір у режимі «пише Obscura»: запустіть етап через start_run».
- `start_run(story_id, action, scene_id=None, confirm=False, budget_limit_usd=None)`, `action ∈ {brief, draft, edit, memory, publication_suggest}`; `get_run(run_id, cancel=False)`. Інструментів — 25.
- Довгий запуск не чекає в одному виклику: `start_run` повертає одразу.
- Тести без платних викликів: фіктивний шлюз або `readiness.preview` підмінено.

## Review Focus

1. `start_run` без `confirm` нічого не ставить у чергу (тест у задачі 2).
2. Повтор `start_run(confirm=true)` після мережевого збою не створює другого запуску — `request_id` клієнта однаковий для тих самих аргументів у межах виклику; повтор з новим викликом — новий запуск (явно в описі інструмента; тест на ідемпотентність сервера в задачі 1).
3. Запуск від інтерфейсу (без позначки) у творі «пише чат» проходить (тест у задачі 1).
4. `memory`, що потребує підтвердження автора, дає помилку з порадою, а не запуск (тест у задачі 2).
5. Скасування чужого запуску від моста не змінює його стану (тест у задачі 1).
