# Експорт плану й персонажів у Markdown

Дата: 2026-11-13
Статус: затверджено (13.11.2026)
Spec-review: agy/gemini-3.8-flash @ f20dbd4 (author: claude) — 6 findings: 6 fixed, 0 rejected

## Для власника

### Мета

Автор може одним файлом забрати поточний план твору й описи персонажів, щоб перечитати їх, переслати чи тримати поруч, не відкриваючи редактор.

### Що зміниться для тебе

- У діалозі «Експорт…» у списку форматів з'являється пункт «План і персонажі (.md)».
- Файл містить назву твору, загальні нотатки плану (вступ до сцен з імпортованого плану, якщо він був), план кожної активної сцени в порядку читання й картки персонажів з їхніми відомостями. Сцена з порожнім планом позначена курсивом «План не створено.». Якщо карток ще немає, а файл персонажів імпортовано, у розділ «Персонажі» потрапляє його текст; якщо немає нічого — курсивом «Персонажів не додано.».
- Біля відомості, доступної не з початку історії, стоїть «(від сцени N: Назва)». Якщо ту сцену перенесено в кошик, стоїть «(від сцени в кошику)».
- Цей пункт працює й тоді, коли прози ще немає: пункт меню «Експорт…» більше не вимикається через відсутність прози, а причину показує сам діалог для книжкових форматів. Як і для книги, перед експортом треба зберегти ручні правки.
- Файл призначений для читання. Назад його імпортувати не можна: для імпорту лишаються окремі шаблони плану й персонажів.
- Посилання на маніфест для цього пункту немає, бо це не книга.

### На чому стоїть рішення

1. Експорт плану й персонажів — одна опція в наявному списку форматів, формат `.md`. `[вимога власника]`
2. Файл просто читабельний, не у форматі шаблонів імпорту. `[вимога власника]` (13.11.2026)
3. Наявний експорт (`application/exports.py::export_story`) будує книгу лише з прози: він вимагає прозу, рахує неповноту й пише маніфест. Плану й персонажів у ньому немає. `[проба]` (П1)
4. План сцени — текст поточної голови `plan`, а для сцени без збереженої версії плану — поле `scene.beats` (так само читає `generation/context.py`); загальні нотатки — вступ активного `source_plan` (`split_plan(text)[0]`). `[проба]` (П2)
5. Картки персонажів читаються з того самого знімка: `load_characters(view.read_text(story.characters_version_id))` (як `characters/service.py::_cards`); без карток — текст активного `source_characters`. `[проба]` (П3)

### Ключові рішення

1. **Окремий запит, не формат книги.** `GET /api/stories/{id}/plan.md` будує файл із поточного стану під час запиту й віддає його як вкладення `<назва>-план.md`. На диску нічого не зберігається, маніфесту немає. Відкинуто додавання формату в `export_story`: той механізм розрахований на незмінну книгу з маніфестом і перевіркою SHA-256, а план — робочий знімок, який читають зараз. (Моє рішення.)
2. **Доступність у діалозі.** Пункт меню «Експорт…» (`#export-story`) вимикають лише незбережені правки, збереження й поточний експорт, бо формат обирають уже в діалозі. Відсутність прози блокує лише «Створити файл» для книжкових форматів. Для плану діалог не вимагає прози й ховає галочку неповного твору; незбережені правки й збереження блокують так само, як для книги, бо інакше файл не містив би останніх змін. (Моє рішення.)
3. **Що потрапляє у файл.** Лише активні сцени (без кошика), в порядку читання; поточні голови плану (або `beats`), а не історія версій; картки в збереженому порядку. Усе читається з одного `repo.context_view(story_id)`. Відомість, прив'язана до сцени в кошику, отримує позначку «(від сцени в кошику)», а не помилку. Службові ідентифікатори версій не потрапляють. (Моє рішення.)
4. **Мова підписів** — мова твору (`story.language`): «План», «Персонажі», «План не створено.», «Персонажів не додано.», «від сцени», «від сцени в кошику» та англійські відповідники. Заглушки виводяться курсивом Markdown. (Моє рішення.)

### Що стане гірше

- Файл не імпортується назад.
- Описи персонажів ідуть без джерел і цитат, з яких вони взяті.
- MCP-інструмент `export_book` цього пункту не отримує.

## Обсяг

Один PR на `main`, після злиття PR з виправленнями діалогу експорту (той самий `export-form.js`).

- `src/storygen/application/plan_export.py` (новий): `plan_markdown(repo, story_id) -> tuple[str, bytes]` — ім'я файлу й вміст UTF-8. Усе читає з одного `view=repo.context_view(story_id)`: історію, активні сцени (`list_scenes`), текст голови `plan` кожної сцени (`view.read_text`) або `scene.beats`, вступ активного `source_plan`, картки (`load_characters(view.read_text(story.characters_version_id))`) або текст активного `source_characters`. Для позначки «від сцени» шукає сцену серед активних; не знайдено — «від сцени в кошику». `read_character_material` не викликається: він відкриває окремий знімок. Текст плану й відомостей іде як є (це Markdown автора); назви твору, сцен і персонажів екрануються `escape_plain_markdown`.
- Структура файлу:
  ```
  # <Назва твору>
  ## План
  <загальні нотатки, якщо є>
  ### Сцена N: <Назва>
  <текст плану або «_План не створено._»>
  ## Персонажі
  ### <Ім'я>
  - <відомість> (від сцени N: <Назва>)
  ```
  Якщо карток немає, але є `source_characters` — його текст як є; якщо немає нічого — «_Персонажів не додано._».
- `src/storygen/web/routes_exports.py`: `GET /api/stories/{id}/plan.md` → `Response(media_type='text/markdown; charset=utf-8', Content-Disposition: attachment; filename*=UTF-8''…)`. `long_prose_guard.py` — дозволити, як і книжковий експорт.
- `templates/story.html`: `<option value="plan">` з підписом `export.plan_option` («План і персонажі (.md)» / «Plan and characters (.md)»).
- `static/export-form.js`: `#export-story` вимикають лише `dirty`, `saving` і `busy`; відсутність прози стає причиною лише для `#export-submit` при книжковому форматі. Для `plan` — причина недоступності лише незбережені правки або збереження; галочка `#export-incomplete` прихована; сабміт не викликає `POST /export`, а показує посилання «Завантажити план і персонажів» на `GET …/plan.md` без посилання на маніфест.
- SPEC.MD: у EXPORT-001 — абзац про експорт плану й персонажів і Scenario EXPORT-001-S06; traceability.
- `docs/site/{uk,en}/publication.md`: пункт про «План і персонажі (.md)»; `check_site.py --rehash publication`.
- Тести: `tests/application/test_plan_export.py` (сцена з планом-версією, сцена лише з `beats`, сцена з порожнім планом, кошик, відомість «від сцени» і «від сцени в кошику», лише `source_characters`, без персонажів, загальні нотатки, екранування назви, англійська мова); маршрут — заголовки й `text/markdown`; `tests/web/js/exports.mjs` — без прози `#export-story` доступна, книжковий формат показує причину, `plan` доступний, без `POST /export`, галочка прихована.
