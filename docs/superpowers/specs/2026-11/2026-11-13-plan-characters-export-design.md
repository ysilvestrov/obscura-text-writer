# Експорт плану й персонажів у Markdown

Дата: 2026-11-13
Статус: чернетка

## Для власника

### Мета

Автор може одним файлом забрати поточний план твору й описи персонажів, щоб перечитати їх, переслати чи тримати поруч, не відкриваючи редактор.

### Що зміниться для тебе

- У діалозі «Експорт…» у списку форматів з'являється пункт «План і персонажі (.md)».
- Файл містить назву твору, загальні нотатки плану (вступ до сцен з імпортованого плану, якщо він був), план кожної активної сцени в порядку читання й картки персонажів з їхніми відомостями. Сцена без плану позначена «План не створено».
- Біля відомості, доступної не з початку історії, стоїть «(від сцени N: Назва)».
- Цей пункт працює й тоді, коли прози ще немає. Як і для книги, перед експортом треба зберегти ручні правки.
- Файл призначений для читання. Назад його імпортувати не можна: для імпорту лишаються окремі шаблони плану й персонажів.
- Посилання на маніфест для цього пункту немає, бо це не книга.

### На чому стоїть рішення

1. Експорт плану й персонажів — одна опція в наявному списку форматів, формат `.md`. `[вимога власника]`
2. Файл просто читабельний, не у форматі шаблонів імпорту. `[вимога власника]` (13.11.2026)
3. Наявний експорт (`application/exports.py::export_story`) будує книгу лише з прози: він вимагає прозу, рахує неповноту й пише маніфест. Плану й персонажів у ньому немає. `[проба]` (П1)
4. План сцени — текст поточної голови `plan` сцени; загальні нотатки — вступ активного `source_plan` (`split_plan(text)[0]`, як у `generation/context.py`). `[проба]` (П2)
5. Картки персонажів повертає `characters/service.py::read_character_material` (ім'я, відомості з доступністю). `[проба]` (П3)

### Ключові рішення

1. **Окремий запит, не формат книги.** `GET /api/stories/{id}/plan.md` будує файл із поточного стану під час запиту й віддає його як вкладення `<назва>-план.md`. На диску нічого не зберігається, маніфесту немає. Відкинуто додавання формату в `export_story`: той механізм розрахований на незмінну книгу з маніфестом і перевіркою SHA-256, а план — робочий знімок, який читають зараз. (Моє рішення.)
2. **Доступність у діалозі.** Для цього пункту діалог не вимагає прози й не показує галочку неповного твору; незбережені правки й збереження блокують так само, як для книги, бо інакше файл не містив би останніх змін. (Моє рішення.)
3. **Що потрапляє у файл.** Лише активні сцени (без кошика), в порядку читання; поточні голови плану, а не історія версій; картки в тому порядку, в якому їх повертає сервіс. Службові ідентифікатори версій не потрапляють. (Моє рішення.)
4. **Мова підписів** — мова твору (`story.language`): «План», «Персонажі», «План не створено», «від сцени» та англійські відповідники. (Моє рішення.)

### Що стане гірше

- Файл не імпортується назад.
- Описи персонажів ідуть без джерел і цитат, з яких вони взяті.
- MCP-інструмент `export_book` цього пункту не отримує.

### Оцінка

- Власник: не названо. Автор: S.
- Розбивка: сервіс і маршрут — 30 %; діалог (пункт, доступність, посилання) — 20 %; тести — 25 %; SPEC, traceability, сайт uk/en — 15 %; перевірки й PR — 10 %.
- Дешевший варіант: зібрати файл у браузері з наявних запитів. Відкинуто: план сцени доступний лише по одній сцені, тож це десятки запитів і дубль логіки збору.

## Обсяг

Один PR на `main`, після злиття PR з виправленнями діалогу експорту (той самий `export-form.js`).

- `src/storygen/application/plan_export.py` (новий): `plan_markdown(repo, story_id) -> tuple[str, bytes]` — ім'я файлу й вміст UTF-8. Читає через `repo.context_view(story_id)`: історію, активні сцени (`list_scenes`), голову `plan` кожної сцени (`read_text`), активний `source_plan`, картки (`read_character_material`). Текст плану й відомостей іде як є (це Markdown автора); назви твору, сцен і персонажів екрануються `escape_plain_markdown`.
- Структура файлу:
  ```
  # <Назва твору>
  ## План
  <загальні нотатки, якщо є>
  ### Сцена N: <Назва>
  <текст плану або «_План не створено._»>
  ## Персонажі
  ### <Ім'я>
  - <відомість> (від сцени N: <Назва>)
  ```
  Якщо карток немає — «_Персонажів не додано._».
- `src/storygen/web/routes_exports.py`: `GET /api/stories/{id}/plan.md` → `Response(media_type='text/markdown; charset=utf-8', Content-Disposition: attachment; filename*=UTF-8''…)`. `long_prose_guard.py` — дозволити, як і книжковий експорт.
- `templates/story.html`: `<option value="plan">` з підписом `export.plan_option` («План і персонажі (.md)» / «Plan and characters (.md)»).
- `static/export-form.js`: для `plan` — причина недоступності лише незбережені правки або збереження; галочка `#export-incomplete` прихована; сабміт не викликає `POST /export`, а показує посилання «Завантажити план і персонажів» на `GET …/plan.md` без посилання на маніфест.
- SPEC.MD: у EXPORT-001 — абзац про експорт плану й персонажів і Scenario EXPORT-001-S06; traceability.
- `docs/site/{uk,en}/publication.md`: пункт про «План і персонажі (.md)»; `check_site.py --rehash publication`.
- Тести: `tests/application/test_plan_export.py` (сцена без плану, кошик, відомість «від сцени», загальні нотатки, екранування назви, англійська мова); маршрут — заголовки й `text/markdown`; `tests/web/js/exports.mjs` — `plan` без прози доступний, без `POST /export`, галочка прихована.

### Поза обсягом

- Імпорт цього файлу назад; MCP `export_book`; збереження файлу в історії експортів.

## Проби

- **П1.** `application/exports.py:14-35`: `export_story` приймає лише `md|txt|fb2|epub|pdf`, будує `Book` через `publication/book.py::capture` (лише проза) і пише маніфест; `download_export` віддає лише файли з маніфестом.
- **П2.** `scene_plan_template.py`: план сцени — вільний текст з полями шаблону; `generation/context.py:386` бере вступ `split_plan(text)[0]` з активного `source_plan`.
- **П3.** `characters/service.py:45-56`: `read_character_material` повертає `cards` (`name`, `entries[].text`, `availability`, `available_from_scene_id`) і список сцен.
