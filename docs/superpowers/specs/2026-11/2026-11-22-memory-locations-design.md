# Явні локації в пам'яті (#67, частина 1)

Дата: 2026-11-22
Статус: чернетка

## Для власника

### Мета

Пам'ять знає, де відбувається сцена: локації з рядка «Локація:» плану стають картками твору, записи пам'яті посилаються на них, а відбір пам'яті для сцени бере записи про це місце й місця, що його містять чи в ньому лежать, — навіть коли в плані й записі місце назване однаково, але без збігу інших слів.

### Що зміниться для тебе

- Рядок «Локація:» плану починає працювати: «Квартира Джорджа / вітальня, потім двір» дає три картки — «Квартира Джорджа», «Квартира Джорджа / вітальня», «двір». Картки створюються самі, коли зберігається план; для наявних творів — один раз під час оновлення застосунку.
- У контексті твору з'являється панель «Локації»: список карток зі сценами, підказки «схоже на…» і кнопки «Злити» / «Не схожі» / «Розділити». Без твого рішення нічого не зливається.
- Зміна рядка «Локація:» позначає завдання, чернетку й пам'ять сцени застарілими — так само, як зараз зміна «Хто бере участь:».
- Етап memory може позначати факти, стани, лінії й події локаціями сцени; промпт memory трохи довшає. Наявна пам'ять не стає застарілою й не переписується: старі записи просто без локацій.
- Предмети, пошук по прозі («кросівки») і опис локації для письменника — поза цією зміною.

### На чому стоїть рішення

- Локації беруться з рядка «Локація:» плану; кілька — через кому або «смислові» слова; вкладеність — через `/`; тотожність — за точним текстом назви; картки створюються автоматично; злиття схожих — лише рішенням людини; починаємо з локацій, предмети — наступна задача `[вимога власника]` (22.11.2026).
- Рядок «Хто бере участь:» уже розбирається під час збереження плану в склад сцени (`apply_description`), а зміна складу позначає залежні версії застарілими `[проба]` (П1).
- Формат відповіді memory (wire v4) має динамічну схему з дозволеними `character_ids` сцени; поле можна додати необов'язковим, не змінюючи версію контракту `[проба]` (П2).
- Актуальність версій не залежить від тексту вбудованого промпту, тож довший промпт memory не робить наявну пам'ять застарілою `[проба]` (П3).
- Відбір пам'яті вже має шари за збігом ID персонажів; шар локацій лягає поруч `[проба]` (П4).
- Роздільники «і», «та», «and» трапляються всередині назв («Сад і город»), тому роздільниками не є `[виведення]`.

### Ключові рішення

1. ID локації детермінований: `loc_` + 16 hex SHA-256 від (ID твору, нормалізований шлях). Таблиця `story_locations` зберігає шлях для показу, батька, час появи, `merged_into` і відхилені підказки. Відкинуто: картки локацій як файл-версія, як у персонажів, — злиття й автостворення в транзакції збереження плану простіші в SQLite, а ID не залежить від порядку появи.
2. Роздільники в рядку: кома, крапка з комою, `→` і окремі слова «потім», «далі», «згодом», «then», «later»; «і», «та», «and» — ні. Шлях `А / Б` дає картки `А` і `А / Б` (батько — `А`); тотожність — за нормалізованим повним шляхом (регістр, пробіли, лапки й кінцева розділова), показ — першим написанням.
3. Злиття — псевдонім: `merged_into` перенаправляє і сцени з цією назвою, і записи пам'яті; текст планів не змінюється; «Розділити» знімає злиття. Відкинуто: переписування рядків планів — змінює авторський текст і робить план застарілим.
4. Підказки схожості детерміновані, без моделі: однакова остання частина шляху, одна назва повністю міститься в іншій як слова, або відстань редагування ≤ 20 % довжини. Відкинуто: підказки планувальника — платний виклик на кожен план і невідтворюваний результат; можна додати пізніше.
5. Пам'ять: необов'язкове `location_ids` у записах журналу й у додаваннях wire v4 для всіх чотирьох категорій; дозволені — локації сцени та їхні предки. Відбір: шар `place` після `present` — записи, чиї локації (після злиттів) збігаються з локаціями сцени, їхніми предками чи нащадками. Відкинуто: wire v5 — несумісний із власними промптами memory з контрактом `/4`.

Розглянуто стандартне: векторний пошук місць і моделі виділення сутностей — відкинуто дослідженням #25 і рішенням власника: шумно, дорожче, непояснювано.

### Що стане гірше

- Помилка в назві місця дає нову картку: «Квартира Джоржа» ≠ «Квартира Джорджа», доки ти не зіллєш їх за підказкою.
- Зміна рядка «Локація:» робить завдання, чернетку й пам'ять сцени застарілими.
- Промпт memory довший на інструкцію й перелік дозволених локацій — трохи більше токенів на етап memory.
- Записи пам'яті, створені до зміни, без локацій: шар `place` працює лише для нової пам'яті (поки сцени не перебудуються).
- Назва з «і»/«та» в рядку не розділяється: «двір і сад» — одна локація.

### Оцінка

- Власник: L або XL залежно від підходу (для повного варіанту з предметами). Автор: усе разом — XL; ця специфікація (лише локації) — L, 2 PR.
- Розподіл: таблиця й ID локацій, розбір рядка, автостворення, міграція наявних творів ≈ 25 %; пам'ять (журнал, wire v4, схема, промпт, відбір, звужений каталог) ≈ 30 %; панель «Локації» зі злиттям і підказками, показ локацій у таблиці пам'яті ≈ 25 %; SPEC, traceability, сайт uk/en ≈ 20 %.
- Дешевший варіант — без панелі злиття (≈ −20 %): дублікати назв лишаються різними локаціями без способу їх поєднати.

### Питання до власника

1. Чи потрібен у картці локації опис, який бачить письменник (як у картках персонажів)? У цій специфікації його немає: картка — лише назва, вкладеність і злиття.

- Міграція бази: таблиці й одноразовий прохід усіх активних сцен (`scene.beats`) з тим самим розбором; сцени без рядка — без локацій. Ревізії сцен міграція не збільшує й версії застарілими не позначає.
- Журнал: `MemoryEvent.location_ids: list[str] = []`; wire v4: необов'язкове `location_ids` у додаваннях усіх категорій; `schema_bounds_v4` отримує дозволені ID (локації сцени й предки); фрагмент контексту `memory_allowed_location_ids` з назвами для моделі; інструкція у вбудованому промпті memory. Невідомий ID — порушення нормалізації (як невідомий персонаж), запис зберігається без нього.
- Відбір: шар `place` у `selection.LAYERS` після `present`; `narrow_catalog` додає стани з локаціями сцени.

**PR 2 — інтерфейс і документація:**

### Новий Requirement і Scenarios

`MEMORY-LOCATIONS` — картки локацій із плану, злиття й шар відбору. Scenarios:

- `MEMORY-LOCATIONS-S01` — розбір рядка: кома, `;`, `→`, «потім»/«далі»/«згодом»/«then»/«later» розділяють; «і»/«та»/«and» — ні; `А / Б` дає `А` і `А / Б`; однаковий нормалізований шлях — та сама картка, інший текст — інша.
- `MEMORY-LOCATIONS-S02` — збереження плану створює картки й `Scene.location_ids`; зміна рядка позначає завдання, чернетку й пам'ять застарілими; міграція заповнює наявні сцени без зміни ревізій і без застарілості.
- `MEMORY-LOCATIONS-S03` — злиття перенаправляє сцени й записи пам'яті, «Розділити» повертає; текст планів не змінюється; підказки схожості детерміновані, відхилена пара більше не пропонується.
- `MEMORY-LOCATIONS-S04` — memory: дозволені в схемі лише локації сцени та їхні предки; невідомий ID відкидається з порушенням; старий журнал без поля читається.
- `MEMORY-LOCATIONS-S05` — відбір: запис про `А` потрапляє в шар `place` сцени в `А / Б`, запис про `А / Б` — у сцену в `А`; запис зі злитої локації — як про цільову.
