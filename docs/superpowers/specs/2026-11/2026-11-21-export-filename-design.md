# Ім'я файлу експорту з автора, назви книги й дати (R-42, #236)

Дата: 2026-11-21
Статус: затверджено 2026-11-21
Spec-review: agy/gemini-4-argon @ 620440a (author: claude) — 3 findings: 3 fixed, 0 rejected (fallback: codex — usage limit)

## Для власника

### Мета

Завантажений експорт книги називається так, що з імені видно автора, книгу й день експорту, наприклад `Автор — Назва — 2026-11-21.epub`, а не технічний `<id>.epub`. Кілька експортів у «Завантаженнях» розрізняються без відкриття.

### Що зміниться для тебе

- Нові й уже створені експорти схеми 2 (MD, TXT, FB2, EPUB, PDF) завантажуються під читабельним ім'ям, а найстаріші MD/TXT без метаданих у маніфесті — як і раніше, під технічним; на диску застосунку файли й маніфести лишаються під технічним ID, нічого не перейменовується й не мігрує.
- Маніфест (`<id>.manifest.json`) і файл плану (`<назва>-план.md`) не змінюються.
- Від тебе нічого не потрібно; незворотних дій немає.

### На чому стоїть рішення

- Ім'я: автор, назва книги й дата експорту; сховище й маніфест лишаються під ID `[вимога власника]` (issue #236).
- Кома й крапка в імені не дозволені — замінюються пробілом `[вимога власника]` (21.11.2026).
- Маніфест кожного експорту схеми 2 вже містить ефективну назву книги, підписи авторів і момент створення; маніфест старого формату (без `schema_version`, лише MD/TXT) цих даних не має `[проба]` (П1, П4).
- Діалог експорту завантажує посиланням з порожнім `download`, тож ім'я задає лише заголовок `Content-Disposition` сервера `[проба]` (П2).
- MCP `export_book` повертає лише посилання, без імені файлу, тож його контракт не змінюється `[проба]` (П3).
- Застосунок локальний, тому «місцевий час» сервера — це час комп'ютера автора `[виведення]`.

### Ключові рішення

1. Ім'я складається під час завантаження з маніфесту цього експорту, а не записується в маніфест під час експорту. Відкинуто: нове поле `download_name` у маніфесті — змінює схему, а старим експортам однаково потрібна запасна гілка. Ім'я однаково відповідає книзі на момент експорту: картка в маніфесті — знімок.
2. Вигляд `Автори — Назва — РРРР-ММ-ДД.<формат>`; без авторів частина пропускається; дата — за місцевим часом комп'ютера. Відкинуто: дата UTC — пізно ввечері дає «завтра».
3. Кілька авторів — через « та » (англійська картка — « and »); якщо частина довша за 60 знаків — перший автор і « та інші » (« and others »), а один задовгий автор просто скорочується; уся частина авторів — не довша за 60 знаків. Відкинуто: кома — заборонена власником; «та ін.» — крапка заборонена.
4. ASCII-запасне ім'я в `filename=` — нинішнє технічне `<id>.<формат>`, читабельне — в `filename*` (RFC 6266/5987, UTF-8). Відкинуто: транслітерація — окрема таблиця для кожної мови, а сучасні браузери (вбудований WebView2 теж) беруть `filename*`.

Розглянуто стандартне: `Content-Disposition` з `filename*` за RFC 6266 — прийнято, так уже віддається план (`plan_export.py`).

### Що стане гірше

- Скорочені назви: книга з назвою, довшою за ліміт імені, обрізається; назви, що різняться лише комою чи крапкою, дають однакові імена — у тому самому дні браузер додасть « (1)».
- Старий експорт без метаданих у маніфесті (до схеми 2) і далі завантажується під технічним ім'ям.
- Назва, що складається лише з ком, крапок чи заборонених символів (наприклад «...»), зникає з імені: лишаються автор і дата; якщо немає й автора — технічне ім'я.
- Ще одне правило імені поруч із правилом плану (`<назва>-план.md` лишає коми й крапки) — два правила для схожих файлів.

### Оцінка

- Власник: S. Автор: S — оцінки збігаються.
- Розподіл: функція імені й тести символів, довжини, кирилиці, старих маніфестів ≈ 50 %; заголовок у маршруті й тест API ≈ 15 %; SPEC EXPORT-001, traceability ≈ 20 %; сайт uk/en ≈ 15 %.
- Дешевшого варіанта з тим самим результатом немає.

## Обсяг

- `src/storygen/application/exports.py`: `download_name(manifest, export_id, format) -> str` — читабельне ім'я з маніфесту; `download_export` повертає вміст і ім'я (або окрема функція, що читає вже перевірений маніфест).
- `src/storygen/web/routes_exports.py::download`: для файлу книги — `Content-Disposition: attachment; filename="<id>.<формат>"; filename*=UTF-8''<percent-encoded ім'я>`; для `.manifest.json` — без змін.
- Без змін: `export_story`, схема маніфесту, сховище, `export-form.js`, MCP `export_book`, `plan_markdown`.

### Правила імені

1. Частини: автори (`metadata.authors[].display_name` у порядку картки), назва (`metadata.effective_title`), дата (`created_at` → `datetime.fromisoformat(...).astimezone()` → `YYYY-MM-DD`). Роздільник між частинами — ` — ` (пробіл, тире U+2014, пробіл).
2. Очищення кожної частини: символи `\ / : * ? " < > |`, `,`, `.` і керівні `\x00-\x1f` замінюються пробілом; послідовні пробіли стискаються до одного; краї обрізаються.
3. Автори: порожні після очищення підписи пропускаються; решта з'єднуються через ` та ` (якщо `metadata.card.language` починається з `en` — ` and `). Ліміт частини авторів — 60 знаків разом із суфіксом. Якщо з'єднання довше: при двох і більше авторах — перший автор, скорочений до `60 − len(суфікса)`, + суфікс ` та інші` / ` and others`; при одному авторі — він скорочується до 60 без суфікса.
4. Довжина основи (без `.<формат>`) — не більше 150 знаків: скорочується назва (до мінімуму 1 знак), далі — автори.
   Після кожного скорочення частина знову обрізається з правого краю (`rstrip`), тож пробіл не лишається перед суфіксом чи роздільником.
5. Запасні гілки: немає назви після очищення — частина пропускається; немає валідної дати — частина пропускається; немає ні назви, ні авторів (лишилася б сама дата), маніфест без `metadata` (старий формат) або помилка розбору метаданих — технічне ім'я `<id>.<формат>`. Пошкоджений маніфест і далі дає `integrity_error` до вибору імені (наявна перевірка `download_export`).
6. Розширення — нижній регістр формату з маніфесту (`md`, `txt`, `fb2`, `epub`, `pdf`).

### Новий Scenario

Вимога EXPORT-001 доповнюється абзацом про ім'я завантаження; відомих дефектів немає.

```
<a id="export-001-s07"></a>
#### Scenario: EXPORT-001-S07 — Читабельне ім'я завантаження
- GIVEN експорт книги з двома авторами, назвою з комою, крапкою й забороненим у Windows символом і моментом створення в UTC
- WHEN автор завантажує файл книги
- THEN `Content-Disposition` містить `filename*` UTF-8 з іменем «Автор1 та Автор2 — Назва — РРРР-ММ-ДД.<формат>» без ком, крапок і заборонених символів, з датою за місцевим часом, і ASCII-запасне `filename` = `<id>.<формат>`
- AND без авторів частина автора пропущена, задовгі кілька авторів дають «перший та інші» в межах 60 знаків, один задовгий автор скорочений без суфікса, задовга назва скорочена до ліміту без пробілу на краю
- AND експорт без метаданих у маніфесті або без назви й авторів завантажується під технічним ім'ям, а маніфест — під `<id>.manifest.json`
- AND файли на диску й маніфест лишаються під ID експорту.
```

## Проби

- **П1.** `application/exports.py:37-47`: маніфест має `created_at` (`domain.now()` — `datetime.now(timezone.utc).isoformat()`) і `metadata = snapshot.publication.model_dump(mode='json')`, де `PublicationView` (`publication_models.py:118`) має `effective_title`, `authors: list[PublicSignature]` з `display_name` і `card.language`.
- **П2.** `web/static/export-form.js:39`: `link.download=''` — браузер бере ім'я з `Content-Disposition`; `routes_exports.py:31` зараз віддає `filename="<id>.<формат>"` без `filename*`.
- **П3.** `mcp/bridge.py:671-680`: `export_book` повертає `download_url`, `format`, `complete`, `warnings`, `word_count`, `age_rating` — імені файлу немає.
- **П4.** `download_export` (`exports.py:53-78`) уже перевіряє маніфест і SHA-256 файлу перед віддачею; маніфест без `schema_version` має окрему гілку старого формату.
