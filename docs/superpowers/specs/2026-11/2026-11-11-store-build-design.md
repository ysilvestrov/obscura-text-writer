# Безкоштовна збірка для Microsoft Store (#30, перший крок)

Дата: 2026-11-11
Статус: чернетка

## Для власника

### Мета

Людина без Python і термінала ставить Obscura з Microsoft Store, вводить ключ провайдера в налаштуваннях і пише. Проєкт отримує перший сигнал попиту (встановлення, подяки, записи на платну версію) без постійних витрат.

### Що зміниться для тебе

- З’являється друге «видання» застосунку — для Store. У ньому не можна вибрати найвищий рівень сексуального змісту; решта функцій та сама. Твоя власна робоча копія лишається повною.
- Ключ провайдера можна буде ввести в налаштуваннях; він зберігається у сховищі облікових даних Windows. Файл `.env` працює, як і раніше.
- Встановлена збірка зберігає твори в теці `Obscura` у профілі користувача й сама робить резервну копію перед оновленням бази.
- Тобі доведеться зробити поза репозиторієм: зареєструватися в Partner Center, заповнити сторінку застосунку й анкету вікового рейтингу, подати пакет на сертифікацію, вибрати сервіс подяк і перевірити, що він виплачує у твою країну, записати поріг «попит є».
- Незворотне: назва застосунку в Store резервується за обліковим записом; після публікації користувачі матимуть дані в теці `Obscura`, і змінити це місце без міграції вже не можна.

### На чому стоїть рішення

1. Пріоритет — найдешевша перевірка попиту: безкоштовна збірка в Microsoft Store і добровільні подяки. `[вимога власника]` (11.11.2026)
2. Обмеження збірки для Store — лише рівень рейтингу; функції повні. `[вимога власника]` (11.11.2026)
3. Store забороняє порнографічний і відверто сексуальний контент (політика 11.7), вимагає для генеративного ШІ позначку в описі та спосіб поскаржитися розробнику (11.16), а добровільні подяки через сторонній сервіс дозволяє, лише якщо користувач нічого не отримує натомість (10.8.2). `[проба]` (П1)
4. Рейтинг має три осі з рівнями 0–2; лише рівень 2 сексуального змісту описано як «відвертий сексуальний зміст допустимий». `[проба]` (П2)
5. Ключі провайдерів читаються лише зі змінних середовища та `.env`; поля для введення в інтерфейсі немає. `[проба]` (П3)
6. Застосунок заморожується PyInstaller без змін у коді: збірка 71 МБ стартує за 4 с, віддає сторінку й API та створює базу. `[проба]` (П4)
7. Усе, що упакований застосунок створює в `AppData`, Windows перенаправляє в приватне місце пакета й видаляє разом із застосунком; запис поза пакетом і поза `AppData` дозволений і лишається. `[проба]` (П5)
8. Міграції бази виконуються під час відкриття бази без резервної копії. `[проба]` (П6)
9. Захист локального сервера (лише loopback-хости, відхилення чужого `Origin`) уже є: SECURITY-001. `[проба]` (П7)
10. Обмежувати треба лише сексуальний зміст; рівні 2 насильства й жорстких тем Store не забороняє, а віковий рейтинг застосунку визначить анкета IARC. `[виведення]`
11. Сховище облікових даних Windows і значок у треї працюють із замороженої й упакованої збірки. `[виведення]` — не перевірено; перша задача відповідного PR є пробою, і якщо вона провалюється, специфікація повертається до власника.
12. Сертифікація Store пропустить застосунок, який може згенерувати текст рівня 16+ і 18+ за насильством і темами. `[виведення]` — перевіряється лише поданням.

### Ключові рішення

1. **Видання задається під час збирання, а не налаштуванням.** Скрипт збирання кладе в пакет файл-позначку; без нього застосунок є повним виданням. Відкинуто перемикач у налаштуваннях чи змінну середовища: користувач Store вимкнув би обмеження одним кліком, і збірка перестала б відповідати політиці 11.7. Код публічний, тож це відповідність правилам, а не захист від обходу.
2. **Обмеження рейтингу перевіряє сервер у трьох місцях.** Збереження рейтингу твору чи сцени з рівнем 2 сексуального змісту відхиляється; генерація для сцени з таким чинним рейтингом блокується (це покриває імпортовані й відновлені з копії твори); інтерфейс не показує цей рівень. Відкинуто лише приховування в інтерфейсі: API та імпорт обійшли б його. Фільтра вже згенерованого тексту немає: відповідальність за дотримання рівня несе інструкція рейтингу, а політика 11.16 вимагає каналу скарги, а не фільтра.
3. **Твори живуть у `%USERPROFILE%\Obscura`.** Відкинуто `AppData`: видалення застосунку стерло б твори автора (П5). Відкинуто «Документи»: OneDrive часто синхронізує їх у хмару, що суперечить обіцянці приватності й небезпечно для SQLite. Після видалення застосунку тека лишається; про це сказано в інструкції.
4. **Ключ — у сховищі облікових даних Windows через `keyring`.** Змінна середовища, якщо задана, має перевагу (робоча копія розробника не змінюється). Інтерфейс бачить лише «ключ задано / не задано». Відкинуто файл у теці даних: ключ лежав би відкритим текстом поруч із творами й потрапляв би в резервні копії.
5. **Застосунок без консолі: значок у треї відкриває сторінку в типовому браузері й завершує роботу.** Відкинуто власне вікно (pywebview): фронтенд не перевірено у WebView2 (завантаження файлів, кілька вкладок), а це окремий обсяг тестування. Відкинуто консольне вікно: воно лякає нетехнічного користувача, а його закриття обриває запуск генерації.
6. **Оновлення робить Store; перед міграцією бази застосунок сам робить резервну копію.** Відкинуто Velopack і власну перевірку оновлень: для каналу Store вони зайві й додали б мережевий запит.

- Розглянуто стандартне: підписаний інсталятор із сайту (OV-сертифікат, Velopack) — відкинуто на цей етап, бо це $220–440 на рік до будь-якого сигналу попиту; лишається наступним кроком після перевірки.
- Розглянуто стандартне: покупки всередині Store для розблокування функцій — відкинуто, бо власник вибрав добровільні подяки без обмеження функцій.

### Що стане гірше

- Два видання треба підтримувати й перевіряти: кожна зміна рейтингу чи налаштувань має тест для обох.
- Нова залежність `keyring` і залежність для трея; заморожена збірка може давати хибні спрацювання антивірусів, хоча підпис Store це пом’якшує.
- Модель може порушити інструкцію рейтингу й написати відвертіший текст, ніж дозволяє рівень. Єдина відповідь на це в першому релізі — канал скарги; повторні скарги можуть коштувати місця в Store.
- Сертифікація може відмовити (висновки 10 і 12). Тоді робота над пакуванням MSIX не дасть каналу, але видання, введення ключа, тека даних і запуск без консолі придатні для інсталятора з сайту.
- Подяки — слабкий сигнал: платить зазвичай менше ніж один зі ста. Без порога, записаного до релізу, результат перевірки можна буде трактувати як завгодно.
- Після видалення застосунку тека з творами лишається на диску; хтось сприйме це як сміття.

### Оцінка

- Власник: L. Автор: L (збіг).
- Розбивка: видання, обмеження рейтингу, посилання на подяку, запис і скаргу — 15 %; введення ключа й сховище Windows — 25 %; запуск без консолі, тека даних, резервна копія перед міграцією — 25 %; пакування MSIX, скрипт збирання, інструкції сайту — 25 %; кроки власника поза репозиторієм — 10 %.
- Три PR: (1) видання й обмеження рейтингу; (2) ключ у сховищі Windows; (3) запуск, тека даних, резервна копія, пакування й інструкції. Крок поза репозиторієм — подання в Store.
- Дешевший варіант (M, два PR): ключ у файлі в теці даних і консольне вікно замість трея. Втрачається захист ключа й зручність для нетехнічного користувача, тобто саме те, заради чого людина ставить застосунок зі Store.

### Питання до власника

1. Тека творів `%USERPROFILE%\Obscura` (рішення 3) — згода? Альтернатива — питати теку під час першого запуску; це додає екран і задачу.
2. Чи обмежувати у виданні для Store також рівень 2 насильства й жорстких тем (висновок 10)? Рекомендую ні: політика цього не вимагає, а обмеження звужує аудиторію перевірки.
3. Який сервіс подяк і куди веде «повідомте про платну версію»? Адреси задаються під час збирання, тож відповідь потрібна до подання в Store, а не до початку робіт.

## Проби

- **П1. Політики Store.** Прочитано Microsoft Store Policies 7.20 (14.09.2026), https://learn.microsoft.com/en-us/windows/apps/publish/store-policies. 11.7: «must not contain or display content that a reasonable person would consider pornographic or sexually explicit». 11.16: позначити живий генеративний ШІ в метаданих і в Partner Center; згенерований вміст має відповідати політикам; дати користувачам спосіб повідомити розробника про неприйнятний вміст. 10.8.2: добровільні пожертви — через Microsoft payment request API або безпечний сторонній API; якщо користувач отримує натомість цифрові товари чи функції — лише покупки Store; використання стороннього API позначається в Partner Center.
- **П2. Рейтинг.** `src/storygen/domain.py`: `ContentRating` має `sexual`, `violence`, `themes`, кожне `Literal[0,1,2]`. `src/storygen/rating/instructions.py`: рівні сексуального змісту — «без сексуального змісту; романтика без еротичних подробиць», «дорослий сексуальний зміст без графічних подробиць», «відвертий сексуальний зміст допустимий». Рейтинг зберігають `PUT /api/stories/{id}/content-rating` і `PUT /api/scenes/{id}/content-rating`; перед генерацією діє `rating/guard.py::enforce_rating`.
- **П3. Ключі.** `providers/client.py` і `generation/worker.py` беруть ключ з `os.environ[<key_env>]`; `web/app.py` викликає `load_dotenv(settings.env_file)`. Запису ключа з інтерфейсу в коді немає.
- **П4. Заморожування.** У `C:\tmp\frz`: чисте віртуальне середовище, `pip install ".[web,publication,local-tokens]" pyinstaller`, `PyInstaller --onedir --collect-data storygen --collect-submodules storygen entry.py`. Результат: `Build complete`, `dist/obscura` 71 МБ. Запуск `obscura.exe --data-dir … --port 8791`: відповідь 200 на четвертій секунді для `/`, `/static/i18n.json` і `/api/stories` (`[]`); у теці даних з’явилися `storygen.sqlite3` і `worker.lock`. Не перевірено: експорт публікації, локальні токенізатори, робота без консолі.
- **П5. Файлова система MSIX.** https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes (30.09.2026): нові файли в `AppData` пишуться в приватне місце користувача й пакета; під час видалення застосунку видаляються «any redirected writes to AppData»; запис усередину пакета заборонений; запис поза пакетом «allowed if the user has permissions». На машині не перевірено: Windows SDK (`makeappx`) не встановлено.
- **П6. Міграції.** `storage/database.py` послідовно застосовує `migrations/00N_*.sql` під час відкриття бази; `create_backup` викликає лише `maintenance.py` (команда `storygen backup`).
- **П7. Локальний сервер.** `SPEC.MD`, SECURITY-001: застосунок обслуговує loopback-хости й відхиляє змінювальні запити з чужим `Origin`; `server.py` слухає `127.0.0.1`, типовий порт 8765.

## Технічний опис

### Видання

- `AppSettings.edition: Literal['full','store']`, типово `full`. Джерело — файл `storygen/edition.json` у пакеті (`{"edition":"store","support_url":…,"waitlist_url":…,"report_url":…}`), який створює скрипт збирання. Файла немає в репозиторії та у звичайному встановленні з вихідного коду.
- `GET /api/app-info` повертає `edition`, `max_rating` (`{"sexual":1,"violence":2,"themes":2}` для `store`, усі 2 для `full`), `version` і три адреси. Секретів не містить.
- Адреси порожні — відповідного посилання в інтерфейсі немає. Посилання відкриваються в браузері; застосунок нічого на них не надсилає.

### Обмеження рейтингу (видання `store`)

- `update_story_rating` і `update_scene_rating` відхиляють рейтинг, що перевищує `max_rating`, авторським повідомленням; стан не змінюється.
- `enforce_rating` перед генерацією відхиляє сцену, чий чинний рейтинг перевищує `max_rating` (твір, створений у повному виданні, імпортований або відновлений з копії). Повідомлення каже знизити рейтинг сцени чи твору. Читання, редагування вручну й експорт таких творів не блокуються.
- Інтерфейс рейтингу бере `max_rating` з `/api/app-info` і не показує недоступні рівні.
- У повному виданні поведінка не змінюється.

### Ключі провайдерів

- Порядок пошуку ключа для `key_env`: змінна середовища (включно з `.env`) → запис `keyring` (служба `Obscura`, ім’я — назва змінної) → немає.
- `GET /api/provider-keys` повертає для відомих назв змінних лише `{"name":…,"source":"env"|"store"|null}`. `PUT /api/provider-keys/{name}` зберігає значення у сховищі, `DELETE` видаляє. Значення ніколи не повертається, не логуються й не потрапляють у контекст спроб і резервні копії.
- Зміна діє на наступний запит до провайдера без перезапуску.
- Якщо сховище недоступне (немає бекенда `keyring`), `PUT` повертає авторську помилку з порадою задати змінну середовища; решта застосунку працює.
- SECURITY-002 розширюється: ключ може надійти від інтерфейсу до сервера, але ніколи у зворотному напрямку.

### Запуск установленої збірки

- Точка входу `storygen.desktop:main` (віконний виконуваний файл без консолі). Звичайний `storygen` не змінюється.
- Тека даних: `%USERPROFILE%\Obscura`; `--data-dir` її перевизначає. Журнал — `logs/obscura.log` у теці даних з обмеженням розміру.
- Порт: 8765, якщо вільний; інакше вільний порт. Адреса записується в `server.json` у теці даних. Другий запуск, знайшовши живий сервер за `server.json`, лише відкриває сторінку й завершується.
- Значок у треї: «Відкрити Obscura», «Тека творів», «Вийти». «Вийти» зупиняє сервер так само, як Ctrl+C, і чекає завершення поточного запису.
- Без телеметрії й без перевірки оновлень.

### Резервна копія перед міграцією

- Перед застосуванням першої незастосованої міграції до наявної бази `desktop` викликає `create_backup` у `backups/pre-migration-<версія>-<час>` у теці даних і лише після успіху відкриває базу. Нова порожня база копії не потребує.
- Якщо копію створити не вдалося, застосунок не мігрує й показує помилку з шляхом журналу.
- Зберігаються три останні такі копії.
- Для запуску з вихідного коду (`storygen`) поведінка не змінюється.

### Пакування

- `scripts/build_store.py`: чисте середовище → PyInstaller (каталог, без консолі, дані пакета `storygen`) → `edition.json` → маніфест MSIX (повна довіра, `runFullTrust`) → `makeappx pack`. Версія — з `pyproject.toml`. Адреси посилань — аргументи скрипта.
- У пакет не входять `codex_cli` (рішення власника), MCP-міст, інструменти розробки й тести.
- Локальна перевірка — встановлення пакета, підписаного самопідписаним сертифікатом; у Store пакет підписує Microsoft.
- Збирання ручне на машині з Windows SDK; автоматизація в CI — поза цією специфікацією.

### Документація

- `SPEC.MD`: нові вимоги з Scenario й записами traceability для видання й обмеження рейтингу, сховища ключів, запуску встановленої збірки, резервної копії перед міграцією й пакування; оновлення SECURITY-002.
- Сайт (`docs/site/{uk,en}/`): встановлення зі Store, введення ключа, де лежать твори й що лишається після видалення, обмеження рейтингу у виданні Store, політика приватності для сторінки Store.
