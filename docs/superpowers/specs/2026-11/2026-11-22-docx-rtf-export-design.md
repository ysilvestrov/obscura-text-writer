# R-43 — Експорт DOCX і RTF для редактури

Дата: 2026-11-22
Статус: чернетка
Spec-review: —

GitHub [#268](https://github.com/ysilvestrov/obscura-text-writer/issues/268). Перший із чотирьох пакетів сценарію «редактура книги зовнішнім редактором» (R-43 → R-44 → R-45 → R-46).

## Для власника

**Мета.** Автор може віддати закінчену книгу зовнішньому редактору у файлі Word (DOCX) або RTF, оформленому як рукопис. DOCX містить невидимі мітки сцен, за якими пізніший імпорт редакції (R-46) розкладе повернений текст назад по сценах.

**Що зміниться для тебе.**
- У діалозі «Експорт…» і в MCP `export_book` з'являться два формати: «Word (.docx)» і «RTF (.rtf)». Правила ті самі, що для решти форматів: обрана проза, без кошика, дозвіл на неповний твір, маніфест, читабельне ім'я файлу.
- Робити нічого не треба. Після злиття варто один раз відкрити експорт власної книги у Word: автоматичні тести перевіряють структуру файлу, але не те, як його показує Word.
- Незворотного нічого: нові файли лише додаються до наявних експортів.

**На чому стоїть рішення.**
- DOCX збираємо самі, без нових бібліотек `[вимога власника]`.
- DOCX — рукопис для редактури; для друку лишається PDF `[вимога власника]`.
- Word відкриває вручну зібраний мінімальний DOCX (стилі, закладки, колонтитул, властивості файлу) без відновлення; розриви сторінок працюють `[проба]` (див. «Проба Word»).
- Приховані закладки `_os<ID сцени>` і власні властивості файлу переживають правку заголовка сцени з рецензуванням, примітку й збереження у Word `[проба]`.
- Word показує вбудовані стилі заголовків мовою своєї версії, тож окремі назви стилів для англомовних книг не потрібні `[проба]` (стиль `Heading2` Word повертає як вбудований «Heading 2»).
- Редактор, який видалить заголовок сцени разом із закладкою, позбавить імпорт цієї мітки; тоді R-46 шукатиме сцену за заголовком і порядком `[виведення]`.
- RTF у Word показує кирилицю й типографські лапки при кодуванні `\uN`; символи поза BMP (емодзі) потрібно кодувати парою сурогатів `[проба]`.

**Ключові рішення.**
1. **Мітки для імпорту — прихована закладка на заголовку кожної сцени плюс ID твору й експорту у властивостях файлу.** Відкинуто: зіставлення лише за назвами сцен (редактор їх змінює) і видимі маркери в тексті (редактор їх видалить або вони потраплять у публікацію).
2. **Кожна сцена — «Заголовок 2» з нової сторінки; частина — «Заголовок 1» з нової сторінки; назва книги — стиль «Назва».** Рівень заголовка сцени однаковий для пласкої й структурованої книги, щоб запасне розпізнавання R-46 мало одне правило. Відкинуто: сцени суцільним текстом (гірше видно межі сцен для редактора й імпорту).
3. **Оформлення фіксоване, без налаштувань:** A4, поля 2,5 см, Times New Roman 12 пт, полуторний інтервал, відступ першого рядка 1,25 см, номер сторінки внизу, мова тексту як у EPUB/FB2 тієї самої книги, а сцена з власною мовою прози позначена своєю мовою (перевірка правопису у Word). Відкинуто: налаштовуване оформлення (зайвий інтерфейс для одного сценарію).
4. **Титульна сторінка: назва, автори, цикл (якщо є) і кількість слів; без обкладинки й змісту.** Відкинуто: обкладинка й зміст (це для публікації, а не для рукопису).
5. **RTF — без міток, лише для читання й передавання; імпорту RTF немає (R-46).**

Розглянуто стандартне: python-docx — відкинуто, бо це нова залежність у збірці Store, а прихованих закладок і власних властивостей файлу вона однаково не вміє без ручного XML.
Розглянуто стандартне: конвертація з EPUB/HTML через LibreOffice або pandoc — відкинуто, бо потребує сторонньої програми на машині автора.

**Що стане гірше.**
- Два нові формати в підтримці; ручний OOXML може натрапити на випадок, який Word «відновлює». Захист: перевірка архіву перед публікацією і ручна процедура у Word.
- RTF великої книги важчий за DOCX у кілька разів (кожна кирилична літера — `\uN?`).
- Мітки не захищені від редактора: видалений заголовок сцени забирає закладку.

**Оцінка.** Власник: S. Автор: S, на межі M. Розбивка: DOCX-рендерер і перевірка — 35%, RTF — 15%, підключення формату (експорт, завантаження, маршрут, MCP, діалог, i18n) — 15%, тести — 15%, SPEC (EXPORT-001, EXPORT-CLEAN), traceability, сайт uk/en, README/PRODUCT, скіл publish — 20%. Дешевший варіант: лише DOCX без RTF — втрачається формат для редакторів без Word, економія ~15%.

**Питання до власника.** Немає.

## Технічний опис

### Компоненти

- `publication/docx.py`: `render(book) -> bytes`, `validate(content)`, `PROFILE` (оформлення для маніфесту).
- `publication/rtf.py`: `render(book) -> bytes`, `PROFILE`.
- `application/exports.py`: `FORMATS` і `Literal` доповнюються `docx`, `rtf`; рендерер за форматом; `validation` у маніфесті — `'docx':'OOXML structure + scene bookmarks'`, `'rtf':'RTF 1.9 text'`; `format_details` = `{'profile':PROFILE}` для обох.
- `export_download`: регулярний вираз імені приймає `docx|rtf`; `download_name` не змінюється (бере розширення формату).
- `web/routes_exports.py`: `ExportRequest.format`, MIME `application/vnd.openxmlformats-officedocument.wordprocessingml.document` і `application/rtf`.
- `mcp/bridge.py`: `EXPORT_FORMATS` і опис `export_book`.
- `web/templates/story.html` + i18n uk/en: опції «Word (.docx)» і «RTF (.rtf)» у `#export-format`.
- `publication/book.py::capture` без змін: FB2-перевірки автора й жанру не стосуються нових форматів, обкладинка не використовується.

### DOCX

Пакет (zip, `ZIP_DEFLATED`): `[Content_Types].xml`, `_rels/.rels`, `word/document.xml`, `word/_rels/document.xml.rels`, `word/styles.xml`, `word/footer1.xml`, `docProps/core.xml`, `docProps/custom.xml`.

- Мова (рішення автора спеки після builder check): документ — `card.language` картки публікації, як `dc:language` в EPUB/FB2 (тег BCP-47 записується як є в `w:lang` і `dc:language`; RTF — `\langN` лише для `uk`/`en`, інші теги без `\lang`). Сцена з `prose_language`, відмінною від мови документа, отримує `w:lang` (`uk-UA`/`en-US`) у `rPr` кожного свого фрагмента; RTF — `\lang1058`/`\lang1033` в абзацах сцени. Підписи службових рядків («Слів», «Частина N») — за `story.language`, як наявний `book_parts`.
- Стилі: `docDefaults` (Times New Roman для всіх скриптів, 24 півпункти, `w:lang` документа, інтервал `line=360 auto`, `after=0`); `Normal` з `firstLine=709`; `Title` (по центру, жирний 16 пт); `Heading1`/`Heading2` (`name` = `heading 1`/`heading 2`, `keepNext`, `pageBreakBefore`, `outlineLvl` 0/1, без відступу).
- Сторінка: `pgSz` 11906×16838, `pgMar` 1417 з усіх боків; колонтитул із полем `PAGE` по центру.
- Титул: назва (`Title`), автори по рядку, цикл «Назва · N», рядок «Слів: N» / «Words: N» (сума `word_count` сцен, мова за `story.language`).
- Частини: `Heading1` з назвою з `part_starts(book)`.
- Сцени: `Heading2` з назвою; вміст абзацу обгорнуто `bookmarkStart`/`bookmarkEnd` з іменем `_os` + `scene_id` (35 знаків, ліміт Word — 40; префікс `_` робить закладку прихованою) і послідовними `w:id`.
- Абзаци — з `markup.chapter_paragraphs(chapter)`: порожній абзац для порожніх рядків, хвостові порожні відкидаються як у PDF; `run.bold`/`run.italic` → `w:b`/`w:i`; `\n` усередині фрагмента → `w:br`; текст у `w:t xml:space="preserve"`.
- `core.xml`: `dc:title`, `dc:creator` (автори через «; »), `dc:language`.
- `custom.xml`: `ObscuraStoryId`, `ObscuraExportId`, `ObscuraManuscript`=`1` (версія розмітки для R-46).
- Недопустимі для XML 1.0 символи — та сама помилка, що в FB2/EPUB (`book.xml_bytes`-перевірка), текст не вилучається.
- `validate(content)` перед записом: zip читається, усі обов'язкові частини присутні й розбираються як XML, кількість закладок `_os…` дорівнює кількості сцен і їхні імена збігаються з `scene_id` у порядку книги, `custom.xml` містить ID твору й експорту. Порушення → `ValueError`, файл не публікується.

### RTF

- Заголовок: `{\rtf1\ansi\ansicpg1252\deff0\uc1`, таблиця шрифтів (Times New Roman), таблиця стилів (`\s1 heading 1`, `\s2 heading 2` з `\outlinelevel0/1`), розмір A4 і поля в твіпах, `\fs24`, `\sl360\slmult1`, колонтитул `{\footer\pard\qc\chpgn\par}`.
- Титул як у DOCX; частина й сцена — абзаци стилів 1/2 з `\pagebb`; абзаци тексту з `\fi709`; `{\b …}`, `{\i …}`, `\line` для `\n`, `\tab` для табуляції.
- Екранування: `\`, `{`, `}` → `\\`, `\{`, `\}`; символи понад ASCII → `\uN?` (N — знакове 16-бітне); поза BMP — два `\uN?` сурогатної пари. Керівні символи, недопустимі в XML 1.0, дають ту саму помилку, що й DOCX (одне правило для всіх форматів).
- Файл ASCII, без перевірки повторним читанням (формат текстовий, структура будується одним генератором).

### Проба Word

Throwaway-скрипт зібрав мінімальний DOCX за схемою вище (дві сцени, частина, курсив/жирний, колонтитул, `custom.xml`) і RTF. Word 16 через COM:
- `Documents.Open` без відновлення; `Bookmarks.ShowHidden=True` → `_osaaaa…=Сцена 1: Вечір | _osbbbb…=Сцена 2: Озеро`; `CustomDocumentProperties` → `ObscuraStoryId,ObscuraExportId`; стиль абзацу заголовка → `Heading 2`.
- Експорт у PDF з Word дав 4 сторінки (титул, частина, дві сцени) — `pageBreakBefore` працює.
- `TrackRevisions=True`, заміна слова в заголовку сцени й в абзаці, примітка → `Revisions.Count=4`; після `SaveAs2` у збереженому `document.xml` обидві закладки на місці, 2 `w:ins` + 2 `w:del`, є `word/comments.xml`, `custom.xml` збережено.
- RTF: кирилиця й «лапки» відображені; емодзі, закодоване одним `\u` з N поза 16 біт, зникло → потрібна сурогатна пара.

### Зміни специфікації й документації

- SPEC.MD EXPORT-CLEAN поширюється на DOCX/RTF з явним уточненням: приховані закладки й властивості файлу — мітки імпорту, а не службові вставки (не видимі в тексті, не містять статусу); кількість слів на титулі рахує лише наявну прозу й не є попередженням. Сценарій EXPORT-CLEAN-S01 доповнюється новими форматами.
- SPEC.MD EXPORT-001: перелік форматів MD/TXT/FB2/EPUB/PDF/DOCX/RTF; нова вимога `EXPORT-DOCX` зі сценаріями:
  - `EXPORT-DOCX-S01` — структура рукопису DOCX (титул, частини, сцени з нової сторінки, курсив/жирний, мова, без сцен з кошика);
  - `EXPORT-DOCX-S02` — мітки імпорту (закладка на кожну сцену в порядку книги, ID твору й експорту у властивостях; невідповідність блокує публікацію);
  - `EXPORT-DOCX-S03` — RTF (екранування, кирилиця, сурогатні пари, недопустимий символ — помилка);
  - `EXPORT-DOCX-S04` — підключення формату (маршрут, MIME, ім'я завантаження, MCP, опції діалогу);
  - `EXPORT-DOCX-S05` — ручна перевірка у Word (процедура з «Проби Word», причина: Word недоступний у CI).
- `docs/verification/traceability.json`: тести для S01–S04, ручна процедура для S05.
- Сайт: `docs/site/{uk,en}/publication.md` — нові формати й призначення DOCX для редактури; решта сторінок, що перелічують формати експорту (`mcp`, `index`, `first-story`, `book-structure`, `content-rating`, `series`), — лише доповнення переліку; `check_site.py --rehash` для кожної зміненої пари.
- `README.md`, `PRODUCT.md` і скіл `integrations/claude/obscura/skills/publish/SKILL.md` — доповнення переліку форматів; версія плагіна піднімається за чинним правилом пакування плагіна.

### Тести

`tests/authoring/test_docx_exports.py`, `test_rtf_exports.py` за зразком `test_ebook_exports.py`/`test_pdf_exports.py`: пласка й структурована книга, сцена в кошику, Markdown і plain-проза (з символами `<&>`), недопустимий символ, порожня книга з `allow_incomplete`, маніфест (`validation`, `format_details`, SHA), `validate` ловить відсутню закладку й чужий ID; маршрут завантаження (MIME, `filename*`), MCP `EXPORT_FORMATS`, опції шаблону.

## Заявка → доказ

| Заявка | Де записано | Що доводить | Сила |
|---|---|---|---|
| Файл DOCX структурно цілий | маніфест `validation` | `validate` повторно читає zip і всі обов'язкові XML-частини перед записом | сильна для структури; відображення у Word — ручна процедура S05 |
| Кожна сцена має мітку імпорту | закладки в `document.xml` | `validate` звіряє імена й порядок закладок зі `scene_id` книги | сильна на момент експорту; після редактора — не гарантується (виведення вище) |
| Файл належить цьому твору й експорту | `custom.xml` | записується з `book.snapshot.story.id` і `book.export_id`, `validate` перевіряє | сильна |
| Байти файлу не змінено | маніфест `output_sha256` | наявна перевірка `export_download` | сильна |
| Оформлення рукопису | маніфест `format_details.profile` | константа `PROFILE`, з якої будуються стилі | сильна (одне джерело) |
