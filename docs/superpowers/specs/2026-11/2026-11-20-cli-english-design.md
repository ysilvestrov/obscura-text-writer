# Мова текстів поза браузером: службові — англійською, вікна запуску — мовою Windows (#32, R-26)

Дата: 2026-11-20
Статус: затверджено 2026-11-20
Spec-review: agy/gemini-4-argon @ 4f44d48 (author: claude) — 3 findings: 3 fixed, 0 rejected (fallback: codex — usage limit)

## Для власника

### Мета

Англомовний покупець не бачить жодного українського тексту, коли встановлена Obscura не стартує. Усе, що читають лише розробники й діагностика (командні утиліти, журнал, збирання пакета), пишеться англійською, без перекладу.

### Що зміниться для тебе

- **Вікна помилок запуску встановленої збірки** говорять мовою Windows, як меню в треї: українська Windows — українською, будь-яка інша — англійською. У вікні коротка причина (тека даних, пошкоджена збірка, резервна копія перед оновленням бази, сервер не стартував) і шлях журналу. Технічні подробиці (тип помилки, код) — лише в журналі.
- **Утиліти `storygen`, `storygen fsck/backup/restore`, `storygen-eval`, `storygen-budget`, `storygen-tokens`, `storygen-local-tokens`** пишуть англійською: опис у `--help`, помилки, підсумки. Ключі JSON у `storygen-eval --dry-run` стають англійськими (`provider`, `cases`, `calls`, `model`, `characters`, `documents`).
- **Журнал `obscura.log`**, повідомлення перевірки цілісності (`fsck`, разом з її одинадцятьма модулями перевірок), резервної копії, самоперевірки збірки, `packaging.py` і скриптів збирання `scripts/build_store.py`, `scripts/tokenizers_notices.py` (включно з текстом третьосторонніх ліцензій у збірці) — англійською.
- Вебінтерфейс, тексти MCP для чату, промпти й скрипти документації та сайту в `scripts/` (`check_docs.py`, `verify.py`, `check_site.py`, `build_site.py` тощо) не змінюються.
- Нічого незворотного: формат даних і бази не змінюється.

### На чому стоїть рішення

- Службові тексти для розробників і діагностики — лише англійською; локалізувати лише те, що бачить покупець `[вимога власника]`.
- Тексти MCP у #32 не чіпати (варіант А) `[вимога власника]`.
- Покупець Store поза браузером бачить лише меню трею (уже локалізоване) і вікна відмови запуску (коди 2, 3, 4 і нестворена тека даних); вікно складається з `reason` + «Подробиці в журналі» `[проба]` (П1).
- Тексти `integrity.py` і її модулів `storage/*_checks.py`, `backup.py`, `build_edition.py`, `pre_migration.py`, `self_check.py`, `build_manifest.py`, `packaging.py` не доходять до HTTP-відповідей: їх викликають лише CLI, запуск desktop і збирання `[проба]` (П2).
- Тексти `locking.py`, `billing/models.py`, шлюзу й модулів оцінювання доходять до веб-запусків і перекладаються каталогом `i18n.json` за українським оригіналом; змінити їх — зламати англійський вебінтерфейс `[проба]` (П2).
- Ніхто не читає українські ключі JSON `storygen-eval --dry-run`: їх немає в тестах, на сайті й у README `[проба]` (П3).
- Спосіб визначити мову Windows для вікна вже є й перевірений для трею (`desktop_tray.system_locale`) `[проба]` (П1).

### Ключові рішення

1. **Межа за читачем, а не за файлом.** Англійськими стають лише тексти, що доходять до консолі, журналу чи артефактів збирання і не доходять до HTTP/MCP. Тексти спільних із вебом модулів, які друкує CLI (помилки бюджету, шлюзу, блокування теки), лишаються як є. Відкинуто: перекласти все поза `web/` (ламає каталог веб-діагностики, П2).
2. **Вікно відмови — стала фраза для кожного коду мовою Windows + шлях журналу**, технічна причина — в англійському журналі. Відкинуто: показувати `str(error)` у вікні, як зараз (тоді англійська технічна причина з'явилася б в українському вікні, або довелося б локалізувати службові модулі).
3. **Порівняння «призначення вже існує» за типом, а не за текстом.** `pre_migration` зараз порівнює текст помилки `backup.py`; переклад тексту мовчки зламав би захист чужої копії від перейменування. Вводиться `DestinationTaken(ValueError)`.
4. **Сторожовий тест**: AST-сканування переліку службових модулів не пропускає кириличних рядкових літералів (крім docstring). Без нього правило «службове — англійською» тримається лише на пам'яті.
5. **Зі `scripts/` англійськими стають лише скрипти збирання пакета** (`build_store.py`, `tokenizers_notices.py`): вони разом із `packaging.py` і `self_check.py` пишуть `BUILD-FAILED.txt` і текст ліцензій, тож інакше діагностика збірки була б змішаною. Скрипти документації й сайту (`check_docs.py`, `verify.py`, `check_site.py`, `build_site.py`, `capture_screenshots.py`, `check_ebooks.py`, `check_pdf.py`, `site_common.py`, `skills_stand.py`) обслуговують українську документацію за правилами проєкту й не змінюються. Відкинуто: перекласти всі `scripts/` (суперечить правилу «мова документації — українська»).

Розглянуто стандартне: `gettext`/`argparse` з каталогами `.po` для CLI — відкинуто, бо власник вирішив не локалізувати службові тексти; для п'яти фраз вікна вистачає наявного каталогу `i18n.json`, яким уже користується трей.

### Що стане гірше

- Вивід CLI може бути змішаним: англійські рамки й українська помилка зі спільного модуля (бюджет, шлюз, блокування теки).
- Вікно відмови більше не показує технічної причини (наприклад, `OSError [28]`); її треба шукати в журналі.
- Українськомовний розробник читає журнал і `fsck` англійською.
- Хто розбирав українські ключі `storygen-eval --dry-run` власним скриптом, мусить перейти на англійські (таких споживачів у репозиторії немає).
- Записи `i18n.json` з українськими текстами `backup.py`/`integrity.py` стають невживаними; вони не заважають і лишаються.

### Оцінка

- Власник: **M** (для перекладу лише інтерфейсу, до вибору межі й варіанта А).
- Автор: **S** (верхня межа), один PR, три задачі. Розподіл: ≈55 % — заміна ≈200 механічних літералів у 29 файлах і оновлення тестів, що їх цитують (зокрема ≈20 рядків `tests/test_packaging.py`); ≈25 % — вікна відмови (каталог, вибір мови, `DestinationTaken`); ≈20 % — сторожовий тест, SPEC, traceability, сайт.
- Дешевший варіант: лише вікна відмови й англійські рамки шести CLI, без `integrity`/`backup`/`packaging`/журналу (≈ XS–S). Втрачає: `fsck` і журнал лишаються українськими, правило «службове — англійською» виконано наполовину.
- Фактично: S, 1 PR (#245), 3 задачі.
- Розбіжність одна позначка — без зупинки; оцінка власника була до звуження обсягу (MCP — варіант А).

## Проби

**П1. Що бачить покупець поза браузером.** `src/storygen/desktop.py::main`:

code, reason = 4, 'Запуск зупинено через непередбачену помилку.'

## Технічний опис

### Перелік службових модулів (сторожовий тест)

`server.py`, `maintenance.py`, `evaluation/cli.py`, `billing/cli.py`, `token_budget/cli.py`, `token_budget/local_cli.py`, `desktop.py`, `app_window.py`, `win_tray.py`, `storage/integrity.py`, `storage/{billing,book,character,comment,impact,memory,merge,publication,review,series,summary}_checks.py`, `storage/backup.py`, `storage/pre_migration.py`, `build_edition.py`, `build_manifest.py`, `self_check.py`, `packaging.py`, `scripts/build_store.py`, `scripts/tokenizers_notices.py`. `desktop_tray.py` уже без кирилиці й теж входить у перелік. Перелік задано явно: новий службовий модуль додають до нього.

Тест `tests/test_service_text_language.py` розбирає кожен модуль `ast`, збирає `ast.Constant` типу `str` з кирилицею, виключаючи docstring модулів, класів і функцій, і вимагає порожнього списку з іменем файла й рядком у повідомленні. Тест падає на чинному коді (RED).

### Вікна відмови

- Ключі в `i18n.json` (`uk` і `en`): `desktop.alert.data_dir` (`{p0}` — тека, `{p1}` — клас помилки), `desktop.alert.edition`, `desktop.alert.backup`, `desktop.alert.start`, `desktop.alert.unexpected`, `desktop.alert.log` (`{p0}` — шлях журналу). `translate` підставляє лише нумеровані `{pN}`, а `tests/web/test_localization.py` звіряє їхній набір між мовами.
- `desktop.py`: `_alert_text(key, locale, *values)` бере `translate(key, locale, p0=…, p1=…)` з `web/localization.py`; мова — `desktop_tray.system_locale()`. Імпорт і визначення мови обгорнуті так, що збій дає англійський вбудований текст, а не відсутність вікна (шлях «тека даних не створюється» іде першим, ще до журналу).
- `_run` повертає `(code, key)` замість `(code, str(error))`; `str(error)` пишеться в журнал (`logger.error`), як і зараз.
- Українські тексти вікон: «Obscura не може створити теку даних {p0} ({p1}).», «Ця збірка Obscura пошкоджена: файл видання не читається. Перевстановіть застосунок.», «Резервну копію перед оновленням бази не створено, тому базу не змінено.», «Obscura не вдалося запустити.», «Запуск зупинено через непередбачену помилку.», «Подробиці в журналі: {p0}». Англійські — відповідники.

### `DestinationTaken`

`storage/backup.py`: `class DestinationTaken(ValueError)`, яку `new_destination` кидає замість `ValueError('Каталог призначення вже існує')`. `pre_migration.py` перевіряє `isinstance(error, DestinationTaken)`; константа `DESTINATION_TAKEN` прибирається.

### Англійські тексти

Кожен кириличний літерал модулів з переліку замінюється англійським відповідником зі збереженням змісту, параметрів і кодів (`code` у звіті `fsck`, коди виходу, ключі JSON звітів, крім `--dry-run` `storygen-eval`). Текст третьосторонніх ліцензій у `packaging.py` перекладається англійською. Повідомлення спільних модулів, які CLI друкує через `str(exc)`, не змінюються.

### SPEC, traceability, сайт

- Нова Requirement `R26-CLI-LANG` після `R24-MESSAGES` зі сценаріями `R26-CLI-LANG-S01` (службові тексти англійською; межа спільних модулів) і `R26-CLI-LANG-S02` (вікно відмови мовою Windows і шлях журналу).
- DESKTOP-001: абзац про відмову стартувати й S03 («причина є в журналі й у повідомленні людині» → коротка причина у вікні, подробиці в журналі). Рядки R24 «CLI (R-26) не реалізовані» замінюються посиланням на R26-CLI-LANG. MAINT-001…003, PACKAGING-001: згадка, що вивід англійською.
- Сайт: `install.md` uk/en — речення, що службові команди пишуть англійською; сторінка про встановлену збірку — якщо описує вікно помилки, уточнити (перевірити під час реалізації). Rehash змінених пар.
