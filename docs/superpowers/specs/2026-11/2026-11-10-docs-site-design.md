### Мета

### Що зміниться для тебе

- **Адреса сайту**: `https://ysilvestrov.github.io/obscura-text-writer/` (українська) і `…/en/` (англійська), з перемикачем мови на кожній сторінці.
- **GitHub Pages увімкнено** (10.11.2026) з джерелом «GitHub Actions»; більше твоїх дій для публікації не потрібно.
- **Публікація після злиття.** Кожне злиття в `main`, що змінює інструкції, збирає й публікує сайт без твоєї участі. PR лише збирає й перевіряє сайт, нічого не публікуючи.
- **Нове правило для змін.** Якщо змінено одну мовну версію сторінки (українську чи англійську) без іншої, перевірка документації падає, доки другу не оновлено й пару явно не підтверджено командою `--rehash`.
- **Користувацькі інструкції переїжджають у `docs/site/uk/` і `docs/site/en/`.** Старі файли в `docs/` з інструкціями стають однорядковими посиланнями на нову сторінку, щоб не ламати наявні посилання. Внутрішні плани, звіти й дослідження лишаються в репозиторії, але на сайт не потрапляють.
- Безкоштовно: Pages і Actions для публічного репозиторію не тарифікуються. Cloudflare не потрібен.

### Ключові рішення

1. **Власний невеликий збирач `scripts/build_site.py` на `markdown-it-py` з одним HTML-шаблоном і CSS, із переписуванням посилань `.md` → `.html` і генерацією якорів заголовків.** Відкинуто MkDocs Material: він у режимі підтримки, супровід закінчується 05.05.2027 — через пів року після запуску сайту довелося б мігрувати; двомовність потребує стороннього плагіна.
2. **Окреме дерево користувацьких сторінок `docs/site/{uk,en}/` з маніфестом `docs/site/site.json`** (порядок навігації, пари сторінок, заголовки). Відкинуто збірку з наявних файлів `docs/*.md` як є: вони технічні, без структури для нового автора, і внутрішні звіти лежать поруч.
3. **Синхронізація мов через підтверджені хеші пари.** Файл `docs/site/sync.json` для кожної сторінки зберігає SHA-256 української й англійської версій на момент, коли автор зміни підтвердив, що вони відповідають одна одній (`python scripts/check_site.py --rehash <slug>`). Перевірка падає, коли будь-яка з двох версій змінилася без підтвердження, коли пари немає, коли посилання, якір чи зображення не розв'язується, або коли сторінка посилається на внутрішні матеріали. Відкинуто перевірку лише наявності пари (не ловить застарілий переклад) і хеш лише української версії (не ловить зміну тільки англійської).
4. **Workflow GitHub Actions з двома режимами.** На PR: збірка й перевірка без публікації. На push у `main` зі змінами в `docs/site/**`, `docs/images/**` або збирачі: збірка, перевірка, `actions/deploy-pages` і перевірка доступності опублікованої адреси. Публікації йдуть по одній (`concurrency: pages`), тож повільніша збірка старішого коміту не перезапише новішу. Права мінімальні: `contents: read`, а `pages: write` і `id-token: write` лише в задачі публікації.
5. **Знімки за мовою інтерфейсу**: `docs/images/site/{uk,en}/`, знімаються відтворюваним скриптом на seed «Маяк на пристані» з інтерфейсом відповідною мовою. Відкинуто українські знімки в англійських сторінках: англомовний автор бачив би не той інтерфейс.

- Розглянуто стандартне: MkDocs + Material з `mkdocs-static-i18n` — відкинуто, бо Material у режимі підтримки й супровід закінчується 05.05.2027 (П4), а нова залежність збірки потрібна лише для сайту. Ціна відмови: якорі, переписування посилань і навігацію пишемо самі.
- Розглянуто стандартне: Zensical — відкинуто, бо пре-реліз.
- Розглянуто стандартне: Jekyll, вбудований у GitHub Pages — відкинуто, бо Ruby й Liquid поза стеком проєкту, вбудованої двомовності немає, а перевірку синхронізації все одно треба писати окремо.
- Розглянуто стандартне: Docusaurus — відкинуто, бо Node/React-проєкт заради статичних сторінок; i18n у ньому добре, але вага стека непропорційна.

### Що стане гірше

- Власний збирач — ще один код для підтримки (шаблон, навігація, перемикач мов). Пошуку по сайту в першій версії немає.

- Перенесення інструкцій у нове дерево — великий одноразовий обсяг тексту. Старі посилання на рівні розділів (якорі) можуть вести на сторінку-посилання, а не на потрібний розділ.
- Англійські тексти перекладаю я. Твоя вичитка бажана, але не блокує злиття.

## Обсяг

### PR 1 — механізм і перші сторінки

- `docs/site/site.json`: `{"languages":["uk","en"],"pages":[{"slug":"install","title":{"uk":"…","en":"…"}}, …]}`. Сторінка `docs/site/<lang>/<slug>.md`. Порядок у маніфесті — порядок навігації.
- `scripts/build_site.py [--out _site]`: читає маніфест, рендерить markdown-it-py (CommonMark + таблиці). Посилання на `<slug>.md` і `<slug>.md#якір` у межах маніфесту переписуються на `<slug>.html` і `<slug>.html#якір`. Заголовки отримують `id`: нижній регістр, кирилиця зберігається, пробіли → `-`, решта розділових знаків вилучається, повтори отримують `-2`, `-3`. Обгортає шаблоном `docs/site/template.html` (навігація, перемикач мови на ту саму `slug`, `lang` атрибут), копіює зображення з `docs/images/site/`. Відносні шляхи працюють під підшляхом `/obscura-text-writer/`. Вихід детермінований: однакові джерела дають однакові байти.
- `scripts/check_site.py` (викликається з `scripts/check_docs.py`): кожна сторінка маніфесту існує обома мовами; поточні SHA-256 обох версій дорівнюють записаним у `docs/site/sync.json`; внутрішні посилання, якорі (за тим самим правилом `id`, що в збирачі) й зображення розв'язуються; немає посилань на `docs/superpowers/`, `docs/research/`, `docs/diagnostics/`, `docs/specs/`, `SPEC.MD`, `docs/STATUS.md`; кожне зображення має alt-текст. Помилки зрозумілі: файл, рядок, що робити (`python scripts/check_site.py --rehash <slug>` записує хеші обох версій після перевірки перекладу).
- `.github/workflows/site.yml`: `pull_request` → build + check; `push` у `main` з path-фільтром → build + check + `actions/upload-pages-artifact` + `actions/deploy-pages` + `curl --fail` на адресу сторінки. `concurrency: {group: pages, cancel-in-progress: false}` на рівні задачі публікації: GitHub тримає одну публікацію в роботі й одну в очікуванні, а очікувану замінює новіша, тож опублікованим лишається найновіший коміт. Версії actions закріплені за мажорною версією від GitHub. Модельних викликів і секретів немає.
- Сторінки «Встановлення й запуск» (Windows, Python, `.env`, ключі провайдерів, порт, резервне копіювання; розділ «Інсталятор» з позначкою «з'явиться в #30») і «Перший твір» обома мовами.
- `.gitignore`: `_site/`.
