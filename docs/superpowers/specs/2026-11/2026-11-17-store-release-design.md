# Випуск у Store 1.0: скіли в пакеті, провідник у MCP і залишок #119

Дата: 2026-11-17
Статус: чекає на затвердження
Spec-review: codex/gpt-6.1-sol @ 5ff18ac (author: claude) — 6 findings: 6 fixed, 0 rejected

## Для власника

### Мета

Безкоштовна версія зі Store стає готовою до подання. Автор, який підключив її до Claude, одразу отримує не лише інструменти Obscura, а й порядок роботи: Claude Code — через скіли, Claude Desktop — через скіли або провідник Obscura, інші клієнти — через провідник.

### Що зміниться для тебе

- **Кнопка «Підключити до Claude»** для Claude Code ставить ще й плагін зі скілами. Для Claude Desktop з’являється дія «Скіли для Claude Desktop»: Obscura готує п’ять ZIP-файлів і відкриває теку, а автор завантажує їх у Claude вручну (Customize → Skills → Upload a skill). Автоматично це зробити не можна (П1).
- **Obscura пише у теку творів** копію плагіна (`<тека творів>\claude\marketplace\`) і ZIP-и (`…\claude\skills\`). Після оновлення Obscura копія плагіна й встановлений плагін Claude Code оновлюються самі на наступному старті, якщо скіли вже підключали. Теки `claude\marketplace` і `claude\skills` належать Obscura: копію плагіна вона замінює цілком, лише якщо в теці є її позначка версії; у `claude\skills` перезаписує тільки свої `<скіл>.zip`, чужих файлів не видаляє.
- **Резервні копії теки творів більше не містять `.env`** (там можуть лежати ключі API). Ключі зберігай у сховищі ключів (Store) або окремо; відновлення з копії їх не поверне.
- **Версія 1.0.0**, справжні значки пакета (з наявної емблеми пера), ліцензійні файли залежностей `tokenizers` у повідомленнях.
- **Ти робиш на своїй машині:** встановлюєш Windows SDK, підписуєш і встановлюєш пакет, проходиш ручні перевірки й Windows App Certification Kit за процедурою з `manual.md`. Паралельно — кроки в Partner Center (обліковий запис, назва, анкета IARC, сторінка застосунку). Без цього подання неможливе.
- **Незворотне:** заміна вмісту `claude\marketplace` при оновленні (лише тека з позначкою Obscura). Подання в Store — окремий крок після цієї зміни.

### На чому стоїть рішення

- Скіли в Claude Desktop і claude.ai додаються лише ручним завантаженням ZIP; файлового, програмного чи deep-link способу документація не описує; Free підтримується з увімкненим виконанням коду `[проба]` (П1).
- Каталог локального маркетплейсу Claude Code читається з місця, але встановлений плагін Claude Code копіює в кеш за версією (`~/.claude/plugins/cache/<маркетплейс>/<плагін>/<версія>`), оновлення з тією самою версією нічого не змінює, після підняття версії плагін оновлює `claude plugin update`; `claude plugin install obscura@obscura --scope user` ставить без питань (`-y` потрібен лише для команд, оголошених маркетплейсом) `[проба]` (П1, П2, П5).
- Тека пакета MSIX змінюється з кожною версією й не годиться як шлях для Claude Code; тека творів стала й переживає оновлення `[проба]` (STORE-MCP-001: псевдонім моста існує саме через це).
- Підказки MCP (prompts) запускає користувач, а не модель; чи показує їх Claude Desktop, документація не каже. Модель же сама викликає інструменти `[проба]` (П1).
- Методика в MCP — інструмент-провідник, а не prompts `[вимога власника]` (17.11.2026, варіант А).
- `revise` — окремо від цієї зміни `[вимога власника]`.
- Оцінка власника L `[вимога власника]`.
- Значки пакета можна намалювати з `favicon.svg` (емблема, яку вже показує вебінтерфейс) `[вимога власника]` (відповідь на питання 1).

### Ключові рішення

1. **Одне джерело скілів — `integrations/claude/obscura/`.** ZIP-и для Desktop і текст провідника генеруються з тих самих файлів під час дії, а не зберігаються копіями. Відкинуто: окремі тексти для Desktop/провідника — розійдуться з плагіном.
2. **Стала копія плагіна в теці творів**, оновлюється на старті Obscura, якщо копія є й версія відрізняється; тоді ж Obscura просить Claude Code оновити плагін (Claude Code бере лише нову версію, тож версія плагіна = версія застосунку). Відкинуто: шлях у теці пакета (змінюється з версією); оновлення лише за кнопкою (після оновлення Obscura скіли застаріли б до повторного натискання).
3. **Провідник — інструмент `get_guide(task, reference?)`**, інструкції сервера радять викликати його першим, якщо скіл Obscura не підключено. Відкинуто як основний шлях: MCP prompts (запускає людина, Desktop не перевірено); `.mcpb` `prompts` — ті самі prompts і лише для Desktop. Наявний prompt `start_story` (STORE-MCP-S06) лишається, але його текст тепер генерується зі скіла `start-story`, щоб не було другої версії методики.
4. **Пакет містить `integrations/claude/` як дані поруч з `Obscura.exe`** (тека `claude\`), лише відстежувані git файли. Відкинуто: вбудовувати в `_internal` PyInstaller — плагін не код, а Claude Code має читати його як звичайну теку.
5. **ZIP для Desktop — по одному на скіл**, спільні правила копіюються в `references/rules.md` кожного, посилання `${CLAUDE_PLUGIN_ROOT}/…` переписуються на відносні. Посилання на файли іншого скіла — помилка генерації.

### Що стане гірше

- У Desktop автор має п’ять разів завантажити ZIP і повторювати це після оновлень скілів; Obscura не знає, чи він це зробив.
- Інструментів моста стає 27; провідник дублює скіли в клієнтах, де скіли вже є (інструкції просять не викликати його тоді, але модель може).
- Obscura на старті пише нові файли в теку творів (копію плагіна) і запускає `claude plugin …`, якщо скіли вже підключали. Це ще одне місце, де може не вистачити прав чи місця або де Claude Code відмовить; помилка лише пишеться в журнал і не зупиняє запуск.
- Значки в пакеті лише базового масштабу (без `scale-200` і `targetsize`): на екранах з високою щільністю вони трохи розмиті.
- Значки з favicon — робочі, але не дизайнерські.
- Ручні перевірки на машині власника лишаються ручними; CI для збирання немає.

## Тіло

### 1. Генерація пакетів скілів (`src/storygen/skill_bundles.py`)

Чистий модуль без мережі й без стану:

- `plugin_root(*, frozen: bool, executable: Path, checkout: Path) -> Path | None` — тека `obscura` плагіна: у пакеті `<тека exe>\claude\obscura`, у робочій копії `integrations/claude/obscura`; `None`, якщо її немає.
- `skill_names(plugin: Path) -> list[str]` — теки `skills/*/SKILL.md`, за абеткою.
- `bundle_files(plugin: Path, skill: str) -> dict[str, str]` — вміст ZIP як `шлях → текст`: `<skill>/SKILL.md`, `<skill>/references/*.md` цього скіла і `<skill>/references/rules.md` (копія `shared/rules.md`). У текстах `${CLAUDE_PLUGIN_ROOT}/shared/rules.md` → `references/rules.md`, `${CLAUDE_PLUGIN_ROOT}/skills/<skill>/references/x.md` → `references/x.md`. Будь-яке інше `${CLAUDE_PLUGIN_ROOT}` (файл іншого скіла, невідомий шлях) → `BundleError` з назвою файла.
- `desktop_zip(plugin, skill) -> bytes` — ZIP із теки `<skill>/` в корені (назва теки = назва скіла, як вимагає Claude), UTF-8, без часових міток (відтворюваний вміст).
- `guide_text(plugin, skill) -> str` і `guide_reference(plugin, skill, name) -> str` — для провідника: той самий текст SKILL.md, але `references/x.md` → «`get_guide(task="<skill>", reference="x")`», а `rules.md` → `reference="rules"`.

### 2. Стала копія плагіна (`src/storygen/claude_connect.py`)

- `sync_marketplace(source: Path, target: Path, version: str) -> Literal['created', 'updated', 'unchanged']` копіює з `integrations/claude` лише файли для користувача — `.claude-plugin/` і `obscura/{.claude-plugin,shared,skills}/` (без `tools/` і `evals/`) — у `<тека творів>\claude\marketplace\` атомарно (тимчасова тека поруч → заміна), записує `obscura-version.txt`. Однакова версія й наявні файли → `unchanged`. Наявна `target` без `obscura-version.txt` — не наша тека: `MarketplaceConflict`, нічого не змінюється, інтерфейс показує шлях.
- Окрема позначка `claude-plugin-version.txt` поруч записується лише після коду 0 `claude plugin install`/`update` — тобто що Claude Code уже взяв цю версію.\n- Старт Obscura (`storygen-desktop` і пакет), у фоні після запуску сервера, лише якщо `target` уже існує: версія копії інша — `sync_marketplace`; позначка Claude Code інша за версію застосунку — `claude plugin update obscura@obscura --scope user` (фіксовані argv), якщо знайдено `claude`. Невдача лише пишеться в журнал; позначка не змінюється, тож наступний старт повторить спробу. Якщо копії немає, старт нічого не створює й `claude` не викликає.
- Версія плагіна `plugin.json` дорівнює версії проєкту з `pyproject.toml` (тест).

### 3. Claude Code: плагін разом із мостом

`POST /api/connect/claude-code` після реєстрації моста (як зараз):
1. `sync_marketplace`;
2. `claude plugin marketplace list --json`: маркетплейс `obscura` з іншим шляхом → `claude plugin marketplace remove obscura`; відсутній → `claude plugin marketplace add <target> --scope user`; той самий шлях → `claude plugin marketplace update obscura`;
3. `claude plugin install obscura@obscura --scope user`; якщо плагін уже встановлено — `claude plugin update obscura@obscura --scope user` (кеш Claude Code тримає копію за версією, П5).

Відповідь має окремі поля `mcp` і `skills`: «підключено» для скілів — лише за кодом 0 усіх кроків. Інакше показуються команди для копіювання. Процеси — фіксовані argv, без оболонки, таймаут як зараз. Робоча копія: та сама дія з `integrations/claude` як джерелом.

### 4. Claude Desktop: ZIP-и скілів

`POST /api/connect/claude-desktop/skills` пише `desktop_zip` кожного скіла в `<тека творів>\claude\skills\<skill>.zip` (перезаписує лише ці файли, інших не чіпає), відкриває теку й повертає перелік файлів. Інтерфейс показує кроки: увімкнути «Code execution and file creation», Customize → Skills → «+» → Create skill → Upload a skill, по одному ZIP; після оновлення Obscura — завантажити знову. Запит моста → 403, як решта `/api/connect/`.

### 5. Провідник `get_guide`

Інструмент моста `get_guide(task: str, reference: str | None = None)`:
- `task` — назва скіла з `skill_names`; без `reference` повертає `{task, text, references: [назви]}`, з `reference` — `{task, reference, text}`;
- невідома назва → помилка з переліком допустимих;
- плагіна немає (`plugin_root` → `None`) → помилка «Провідник недоступний у цій збірці».

Читає файли плагіна з диска поруч із мостом (пакет: `<тека obscura-mcp.exe>\claude\obscura`, бо міст лежить у корені пакета поруч з `Obscura.exe`) — сервер Obscura для цього не потрібен. Prompt `start_story(idea)` зберігає аргумент: повертає задум автора (як зараз) і після нього `guide_text(plugin, 'start-story')`; без плагіна — наявний текст як запасний. Інструкції сервера моста: «Якщо скіл Obscura не підключено, спершу виклич `get_guide` для потрібної задачі: start-story, draft-scene, publish, series-bible, setup-models». `next_steps` не змінюється. Тексти скілів згадують `AskUserQuestion` і субагентів Claude: спільні правила вже кажуть, що робити без цих інструментів, тож окремої версії для інших клієнтів немає.

Скіли плагіна SHALL NOT радити `get_guide` (тест S03 його знає як інструмент; згадка в скілах заборонена окремим тестом, щоб Claude зі скілами не читав той самий текст двічі).

### 6. Плагін у пакеті Store

`scripts/build_store.py` копіює відстежувані файли (`git ls-files`) з того самого фільтра, що й `sync_marketplace`, у `<layout>\claude\` і перевіряє: є `obscura/.claude-plugin/plugin.json`, для кожного скіла `bundle_files` без помилок, немає файлів поза фільтром. Формат `package_data_manifest` (лише `src/storygen`) не змінюється; перелік файлів плагіна — окремий рядок звіту збирання. `--self-check` моста викликає `get_guide("start-story")` локально (без сервера).

### 7. Залишок #119 у репозиторії

1. **Версія 1.0.0** у `pyproject.toml` і `plugin.json`; `package_version` → `1.0.0.0`.
2. **Значки:** `scripts/make_store_assets.py` рендерить `favicon.svg` через Playwright (уже є в dev-залежностях) у три некваліфіковані файли тих самих назв і розмірів, що в `packaging.ASSETS` (44, 150, 50 px); PNG комітяться в `store_build/msix/Assets/` замість заглушок. Варіанти `scale-*`/`targetsize-*` потребують `makepri` і `resources.pri` — поза обсягом (відоме обмеження). Тест: файли не однотонні заглушки й мають потрібні розміри. Значок трея лишається своїм (поза обсягом).
3. **Ліцензії `tokenizers`:** повний текст Apache-2.0 і, для кожного crate з `Cargo.lock` тегу `v0.23.3` (`bindings/python`, лише залежності збірки Windows), файли `LICENSE*`/`COPYING*`/`NOTICE*` з його опублікованого архіву `.crate` — файл `store_build/licenses/tokenizers-0.23.3.txt`, згенерований один раз скриптом `scripts/tokenizers_notices.py`; `third_party_notices` вкладає його замість посилання. Crate без жодного такого файла скрипт не пропускає мовчки: потрібен ручний запис у таблиці винятків скрипта (SPDX-текст ліцензії з метаданих і причина). Збирання відмовляє, якщо встановлена версія `tokenizers` не має свого файла.
4. **Середовище збирання:** `docs/packaging.md` описує постійне середовище `.venv-store` на офіційному CPython 3.12 (інсталятор python.org), команду створення й перевірку. Наявна відмова `build_store.py` на нестандартному інтерпретаторі з `--allow-vendor-runtime` лишається без змін; нової перевірки не додається.
5. **Дрібні доробки з #119:**
   - текст «Ключ провайдера відсутній у серверному середовищі» (`providers/client.py`) згадує сховище ключів і місце в налаштуваннях;
   - назва змінної ключа в налаштуваннях приводиться до великих літер при збереженні (сховище приймає лише великі);
   - мова меню трея — мова інтерфейсу Windows (`GetUserDefaultUILanguage`), а не регіональний формат;
   - резервна копія теки творів пропускає `.env` (`storage/backup.py::create_backup`; власник попереджений у розділі «Що зміниться»);
   - тест експорту твору з рівнем 2 у виданні `store`;
   - зайнятий порт 8765 уже вирішено в STORE-MCP-001 (міст читає `server.json`) — пункт закривається без коду;
   - збирання без CI лишається ручним (відоме обмеження).

## Заявка → доказ

| Заявка | Де записано | Що доводить | Сила |
|---|---|---|---|
| Скіли Claude Code підключено | відповідь `/api/connect/claude-code`, поле `skills`; `claude-plugin-version.txt` | код 0 `marketplace add` і `install`/`update` | середня: Claude Code може не перечитати до нового старту — інтерфейс каже «у новій сесії» |
| Копія плагіна актуальна | `obscura-version.txt` у теці копії | збіг із версією застосунку після `sync_marketplace` | сильна для копії; для Claude Code — окрема позначка після коду 0 `plugin update` (П5: Claude Code бере лише нову версію); вміст при тій самій версії не звіряється (робоча копія — розробник) |
| ZIP-и для Desktop готові | перелік у відповіді дії | файли записано й прочитано назад | сильна; що автор їх завантажив — не відомо й не заявляється |
| Ліцензійні файли залежностей `tokenizers` вкладено | файл у `store_build/licenses/` | файли ліцензій з опублікованих архівів кожного crate з `Cargo.lock` тегу | середня: доводить вкладення файлів, які автори crate опублікували; crate без файла — лише за ручним записом із причиною; юридичну повноту не заявляємо |
