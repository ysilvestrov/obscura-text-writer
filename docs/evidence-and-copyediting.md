# Пам’ять за фрагментами й точкова редактура

19 жовтня 2026 року. Зміна наявних етапів після тестів OpenRouter: модель склеювала цитати, губила попередні факти й переписувала сцену під час мовної редактури.

## Нові режими

У налаштуваннях ролі пам’яті доступний єдиний режим **«Операції пам’яті v4 за доказами»** (`memory_mode=evidence_delta`); режим snapshot прибрано. Кожен непорожній рядок вибраної прози отримує стабільний у межах цієї версії ID і точні символьні межі. Нині стандартний формат — wire v4: обов’язкові рішення для кожного слота ядра стану головного героя (`core`) і кожної активної лінії (`threads`), а також згруповані, як у v3, операції за категоріями (`facts`/`timeline` — лише додавання; `character_states`/`open_threads` — додавання, оновлення, закриття), а кожен елемент має `evidence_ids` — від 1 до 3 ID фрагментів. Перший ID дає основну цитату, решта зберігаються як додаткові докази (`supporting_quotes`, до двох). Програма перевіряє ID, бере цитати з оригіналу й застосовує всі операції до журналу атомарно. Модель не копіює старі факти чи source IDs. Власні промпти з контрактами `/2` і `/3` несумісні з v4 і потребують явного перекладу прапорцем «Перевести власний промпт на формат v4». Опис користувача: [перегляд пам’яті](memory-view.md). Початковий формат (історично, до v3) мав єдиний `evidence_id` на запис і додавав записи до snapshot; результати тестів нижче стосуються саме його.

У налаштуваннях редактора доступні **«Точкові мовні правки»** (`edit_mode=patches`). Модель бачить лише нумеровану чернетку; план і майбутні події не надсилаються цьому проходу. Відповідь — JSON із точним оригіналом, заміною та ID фрагмента. Програма відхиляє невідомі/неоднозначні місця, перетини, нові абзаци, надмірне розширення та зміни розпізнаних чисел і заперечень. Перевірка чисел/заперечень виконується також для всього результату, щоб правка частини слова не обходила обмеження. Сумарна площа змін (максимум довжин оригіналу й заміни) не може перевищувати 35% символів сцени.

Це консервативна мовна редактура. Вона може відхилити допустиме переформатування числа чи виправлення заперечення. Лексичні перевірки не охоплюють усіх форм українських числівників і не доводять незмінності сенсу. Імена, підтекст та фактичну правильність кожної заміни ще потрібно оцінювати; категорія правки, названа моделлю, не є доказом якості.

Для обох режимів можна обрати JSON Schema, якщо endpoint її підтримує. При перемиканні очистіть поле власного промпту, щоб використати відповідний стандартний, або адаптуйте свій до нового контракту. Старі режими залишені стандартними для раніше збережених налаштувань; автоматичного перемикання немає. Збережений формат MemorySnapshot і фінальна проза не змінені, міграція історії не потрібна.

Сирий JSON зберігається в partial відповідного StageAttempt, а прийнята версія містить зібраний snapshot або прозу після застосування правок. Залежності, конфлікти ревізій, альтернативні результати й явне відновлення працюють через наявний worker.

## Перевірки

Офлайн: **145 тестів проходять**. Нові тести покривають точність меж фрагментів, невідомі IDs, збереження старих записів без копіювання моделлю, послідовність трьох сцен, structured schemas, виключення плану з точкової редактури, однозначні й непересічні правки, захист чисел/заперечень, незмінність чернетки після відхиленої відповіді та правильні стандартні промпти в API налаштувань.

Незалежний огляд виявив одне зауваження P2: загальне перезавантаження налаштувань після збереження ролі стирало незбережені інші форми. Відтворено через CUA до виправлення; після нього зберігається лише конкретна форма, незбережені письменницький промпт і профіль залишаються на місці. Інших зауважень огляд не повернув. Результат редактури відкрито в браузері; знімок — `artifacts/evidence-pilot/editor-result.png`.

Реальна серія DeepSeek V3.2/DeepInfra — **6/6 окремих етапів завершені**:

| Тест | Результат |
|---|---|
| Три послідовні пам’яті на заморожених текстах попередніх трьох сцен | Усі IDs/цитати валідні, попередні записи збережено; джерел 1 → 2 → 3 |
| Редактура початкової нейтральної чернетки | Прийняті точкові заміни, решта тексту збережена дослівно |
| Редактура тексту з відомими огріхами | «не ваші провина» → «не ваша провина»; особисту розмову не замінено дзвінком |
| Редактура чернетки фотосесії ню | Завершена без відмови; точкові правки, без нової сцени чи заголовка |

Це повторні перевірки пам’яті й редактора на копіях наявної прози, а не новий наскрізний прогін планувальника/письменника. Попередня невдала серія збережена окремо. Після посилення захисту всього тексту всі три фактичні JSON-відповіді редактора повторно застосовані офлайн й дали ті самі збережені результати, без нових платних викликів.

Три автоматичні порівняння редактури через Codex CLI виконані через вебчергу; звіти залишилися candidate/incomplete: немає плану в цих редакторських fixtures, профіль некалібрований. Суддя виявив пропущені мовні/стилістичні огріхи. У текстах, зокрема, лишилися «бачить своє бачення», написання «проектом» та «Лера». Технічне проходження не зараховане як літературне приймання.

Вартість шести запитів за streaming usage OpenRouter — **$0,0048172**. `/generation` окремо підтвердив три з них; для інших трьох повернув 404, їхня звітна вартість збережена з usage. Спільний консервативний резерв враховує й попередню серію та лишається нижче погодженого $1. Художні тексти, exact manifests, SSE, role settings, usage й звіти — у `artifacts/evidence-pilot`, поза Git; ключ не записувався до артефактів.

## Межі результату

Точна цитата підтверджує походження фрагмента, а не логічну правильність висновку моделі. Нові режими ще не перевірені на творі 5000–15000 слів. Збереження повних фрагментів у snapshot збільшує контекст: у цьому тесті оцінка входу пам’яті зросла приблизно 2324 → 6071 → 10246 токенів. Потрібне окреме випробування компактного контексту без втрати посилань. Поліпшення повноти мовної редактури також залишається відкритим.

Після прийняття завдання його ручна правка зберігає це рішення: натисніть «Зберегти» або запускайте чернетку з автоматичним збереженням. Нову, ще неприйняту пропозицію завдання після правки потрібно явно прийняти.
