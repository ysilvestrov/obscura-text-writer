# Пам’ять за фрагментами й точкова редактура

19 жовтня 2026 року. Зміна наявних етапів після тестів OpenRouter: модель склеювала цитати, губила попередні факти й переписувала сцену під час мовної редактури.

## Нові режими

У налаштуваннях ролі пам’яті доступний режим **«Нові факти за фрагментами джерела»** (`memory_mode=evidence_delta`). Кожен непорожній рядок вибраної прози отримує стабільний у межах цієї версії ID і точні символьні межі. Модель повертає тільки нові записи з текстом факту та `evidence_id`. Програма перевіряє ID, бере цитату з оригіналу й додає записи до попереднього перевіреного snapshot. Це явно новий формат відповіді, а не приховане виправлення старих цитат. Модель не копіює старі факти чи source IDs.

У налаштуваннях редактора доступні **«Точкові мовні правки»** (`edit_mode=patches`). Модель бачить лише нумеровану чернетку; план і майбутні події не надсилаються цьому проходу. Відповідь — JSON із точним оригіналом, заміною та ID фрагмента. Програма відхиляє невідомі/неоднозначні місця, перетини, нові абзаци, надмірне розширення та зміни розпізнаних чисел і заперечень. Перевірка чисел/заперечень виконується також для всього результату, щоб правка частини слова не обходила обмеження. Сумарна площа змін (максимум довжин оригіналу й заміни) не може перевищувати 35% символів сцени.

Це консервативна мовна редактура. Вона може відхилити допустиме переформатування числа чи виправлення заперечення. Лексичні перевірки не охоплюють усіх форм українських числівників і не доводять незмінності сенсу. Імена, підтекст та фактичну правильність кожної заміни ще потрібно оцінювати; категорія правки, названа моделлю, не є доказом якості.

Для обох режимів можна обрати JSON Schema, якщо endpoint її підтримує. При перемиканні очистіть поле власного промпту, щоб використати відповідний стандартний, або адаптуйте свій до нового контракту. Старі режими залишені стандартними для раніше збережених налаштувань; автоматичного перемикання немає. Збережений формат MemorySnapshot і фінальна проза не змінені, міграція історії не потрібна.

Сирий JSON зберігається в partial відповідного StageAttempt, а прийнята версія містить зібраний snapshot або прозу після застосування правок. Залежності, конфлікти ревізій, альтернативні результати й явне відновлення працюють через наявний worker.
