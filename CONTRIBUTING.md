# Участь у розробці

Документація проєкту українською. Архітектурний контракт — [SPEC.MD](SPEC.MD).
Зміни компонентів, схем, API, станів, провайдерів або пакування супроводжуйте
оновленням відповідних Requirement/Scenario в тому самому наборі змін.

```powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements-lock.txt
./.venv/Scripts/python.exe -m pip install --no-deps -e ".[web,dev]"
./.venv/Scripts/python.exe -m pytest -q
```

Для JavaScript-перевірок потрібен Node.js у PATH. Їх запускають pytest-обгортки
з потрібними аргументами; без Node.js ці перевірки пропускаються.
Тимчасові тестові дані створюються в ігнорованому `.pytest-tmp/`.

Тести мають працювати з тимчасовими каталогами та підставними провайдерами.
Реальні API-виклики й платні модельні прогони не є частиною звичайної перевірки.
Для відтворення дефектів додавайте лише короткі вигадані приклади.
Авторські плани, чернетки, бази, логи та скріншоти особистих творів не комітьте.

Перед комітом перегляньте `git diff --cached`, включно з новими файлами.
Під час роботи AI-інструментів окремо перевіряйте вкладення й доступний контекст:
ігнорування Git не є межею приватності для таких інструментів.
